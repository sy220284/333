# 主线 CI 按需执行

## 工作方式

主线保留原有的业务代码、78 条工作流、手动迁移与升级入口。自动 PR 检查通过 `.github/workflows/ci-on-demand.yml` 统一调度。

- **Draft PR 普通提交**：快速检查工具链、CI 配置及路由回归；只并行运行由未验收变更文件匹配出的专项检查。
- **同一 PR 连续提交**：取消旧运行并将自上一次成功验收以来的所有变更合并到最新一轮；当历史记录过长或基线不确定时以完整 PR 差异作为安全基准。
- **Draft → Ready for review**：运行主线 25 个专项，包括全量重建与六宿主编译；Ready 之后每次新增提交都继续全量复核。
- **Ready → Draft**：恢复按需策略；不改变 PR 状态之外的功能。
- **main 分支 push**：现有重要工作流仍可按原有 main 分支条件运行；手动升级工作流与源码修改工作流继续独立，不由 PR 验收自动启动。

`build/ci-paths.json` 记录这 25 个检查的原始路径匹配规则；`build/ci-impact.mjs` 负责计算路线。`build/ci-gate-audit.mjs` 在每次基础检查中核对完整接线。新增专项要同时加入路由表和统一调用入口。

依赖锁门禁在 PR 时仅检查锁和生成版本的差异，以只读权限运行；实际依赖升级仍通过独立更新流程执行，避免 CI 自行推送带来重复排队。

## 验收标准

- `node --test tests/ci-routing.test.mjs`
- `node build/ci-gate-audit.mjs`
- 最新 PR 提交的“统一验收结果”成功。Draft 时确认无需运行全量构建；Ready 时确认 25 个专项全部完成，失败必须在统一结果中体现。
