# 333：仅保留交互式会话

## 产品入口

333 的 AI 对话仅通过有真实输入终端和输出终端的交互式界面启动。

- `333` 或发行安装后的 `claude`：进入交互式界面。
- `claude "检查项目"`：带初始消息进入交互式界面，用户仍可追问、审批和继续处理。
- `claude --continue`、`claude --resume`：在交互界面恢复历史会话。
- `claude --help`、`claude --version`：查看帮助或版本；这些只读管理命令可以重定向输出。

## 已移除的面向用户的无界面对话模式

移除 `-p`/`--print`、`--input-format`、`--output-format`（含 JSON 和 stream-json）、结构化输出 Schema、SDK WebSocket 对话入口，以及无界面模型轮次/费用上限、流式消息转发、无界面授权接管和一次性初始化等附属开关。

启动引导层 `src/entrypoints/interactiveOnly317.ts` 在配置初始化和模型调用前统一拒绝这些参数；`src/main.tsx` 重复检查，保证直接调用主入口也无法绕过。主程序中的 `runHeadless` 调用及独立无界面执行分支已经删除，命令帮助隐藏已移除的开关。SDK 的 `createSessionRuntime317` 会明确报错，不再启动依赖 `--print` 的子进程。

普通对话要求标准输入和标准输出均连接终端；将消息通过管道发送或将对话重定向到文件会直接提示改用交互界面。带初始消息的交互会话仍然受完整权限审批和工作区可信检查保护。

## 保留交互模式需要的底层服务

此处的“仅交互式”约束针对 AI 对话启动模式。后台 PTY 宿主、MCP 服务进程、浏览器通信宿主、插件评测工具、自托管 Runner、远程控制桥接和管理子命令仍可按各自协议运行。这些无界面进程用于承载交互能力，本身不是一个可以直接无界面发起 AI 对话的对外入口。

交互会话中的 Agent、工具、权限确认、MCP、技能、插件、会话恢复和界面仍然按原有路径工作。后续新增对话入口必须使用同一入口策略。

## 验收

- `npm run test:interactive`：参数、TTY、管理命令及生产入口静态回归。
- `npm run test:all`：新增交互式模式专项已纳入全量测试。
- 在真实 PTY 中验证普通启动、带初始消息和会话恢复；在非 PTY 中验证 `-p`、JSON/stream-json、SDK 无界面入口均明确失败。
- 2.1.317 原版的无界面对话行为属于本项目有意移除的产品差异，应从新版功能对齐检查中单列，不再要求恢复。其他已升级功能仍按原有基准验收。
