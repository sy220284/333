# 333 · Claude Code 2.1.317 功能验收权威规则

本规则与仓库 [AGENTS.md](../../AGENTS.md) 同步，完整系统审计方法以 [333 全量系统联审规范](../SYSTEM-AUDIT-GUIDE.zh-CN.md) 为准；可复用问题模式按照 [共享审计结论](../SHARED-AUDIT-CONCLUSIONS.zh-CN.md) SC-001～SC-018 处理。

## 行为与升级双基准

- **官方 Claude Code 2.1.317：** 核对功能、接口、参数、状态、副作用、权限、安全、取消、恢复、错误与终端真实行为。
- **PR13/PR14 当前新版技术栈：** 保留已经升级的 Node、Bun、TypeScript 7、MCP v2、原生模块、直接与传递依赖、锁文件和新增功能。
- 遇到官方版本与新版接口不同的情况，验证保留官方语义的新版实现；若是有意增强，建立独立新契约与真实可执行的回归测试，不以降级旧版本换取逐字一致。
- 版本和升级成果保护门禁：`tools/dev/toolchain.lock.json`、`docs/upgrade/pr13-upgrade-protection-baseline.json`、`build/check-upgrade-protection.mjs`。

## 完整验收范围

- `2.1.317-六层完整功能链路.json`：M1–M6 六层，C01–C20 共 20 条用户可达功能链。
- `2.1.317-功能与场景源数据.json`：137 项功能、137 个运行场景，保留此前 102 项功能及 84 个场景的回归集合。
- 366 项增量更新专项独立验证，不能用主链结果替代专项检查，也不能以专项测试通过代替用户可用性。
- `2.1.317-功能链路签收.json`、`2.1.317-功能与场景签收.json` 为正式签收台账；空记录表示尚未正式签收，并不证明能力不存在。

## 每条能力的验收步骤

1. 从当前目标 HEAD 建立官方函数、333 生产入口、状态所有者、真实用户结果的完整路径。
2. 对照 2.1.317 原版的输入/输出、状态变化、安全边界与成功、拒绝、超时、取消、恢复、进程退出行为。
3. 识别本来就应保留的依赖升级差异，以及需要修复的功能缺口、资源泄漏和行为回退。
4. 采用当前新版 API 修复根因，连同跨入口调用、跨平台、边界条件和最末端结果一并验证。
5. 使用与源码提交 SHA 匹配的 CI、真实宿主、原版差分和必要的故障注入作为证据；只有完整闭环才更新台账，未完成的保留待验状态。

## 可执行基础检查

- `node build/compare-317.mjs`、`node build/upgrade-coverage.mjs`
- `node --test tests/compare-317.test.mjs tests/upgrade-coverage.test.mjs`
- `node tools/dev/dev.mjs typecheck:all`、`node tools/dev/type-migration-audit.mjs`
- `node tools/dev/toolchain.mjs check`、`node build/check-upgrade-protection.mjs`
- `bun build/rebuild.mjs`，再运行真实 CLI/PTY、SDK、Gateway、MCP 插件模板、SSE 和六架构适用端到端测试

最终验收需同时满足：官方原有能力保持、已升级的工具和新增能力保持、生产调用链已接通、所有必需测试在当前 HEAD 上通过、资源释放与异常恢复完整、相关签收台账具有可追溯的运行证据。
