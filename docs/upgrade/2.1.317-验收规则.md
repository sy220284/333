# 2.1.317 六层完整实现：严格验收规则

现行唯一实现任务：M1–M6；完整的 20 条链路和每层交付要求见 [六层总方案](2.1.317-六层完整实现升级方案.md) 与 [机器链路清单](2.1.317-六层完整功能链路.json)。

每条功能链从官方 2.1.317 参考程序及对应可读源模块获取：目标版本与 SHA256、函数入口和实际调用者、状态与权限契约、同步/异步及异常语义。优先移植源码、依赖和真实资源；无法移植的目标函数必须有官方 x64 原版真实行为证据支持重写。新版入口、SDK/CLI/界面/宿主消费者均须接通，原有旧版兼容按真实终态清理。

签收一条链至少要有：①官方原版 x64 SHA、函数定位、可复核运行报告；②333 源码位置和实际实现提交、关联 CI；③独立的候选版完整运行报告；④独立的官方/候选差分报告，含正常与失败/权限拒绝、取消/重试/恢复和函数语义检查；⑤必要的跨平台及真实外部服务/IDE/云宿主验证；⑥审核人与时间。三种日志文件不可互相复用；单测通过或静态函数定位只作为中间证据。

正式签收文件：[20 条功能链](2.1.317-功能链路签收.json)，由 `build/upgrade-chain-audit.mjs` 严格读取；历史 102 功能/84 场景：[回归签收](2.1.317-功能与场景签收.json)，由 `build/m1-feature-evidence-registry.mjs` 检查（保留原测试脚本名称以持续验证实际行为）。层完成条件为其所有链签收且前置层已完成。

第 5 层 C13/C14/C15/C20 和跨宿主同步技能 C08 需外部宿主或服务端实测证据。使用 2.1.317 原版无授权 CLI 或单机模拟完成的部分，只登记实际观察范围。

366 条更新的专项工作线独立保留，严格隔离进度与验收，不参与本六层签收器的数据来源。

新目标版本的真实 CI 和全部端到端验收结果必须在 PR 提交的同一 SHA 上复查，避免历史绿色工作流误签收新代码。
