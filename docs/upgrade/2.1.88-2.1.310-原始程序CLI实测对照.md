# 333：2.1.88 与 2.1.310 原始程序 CLI 入口实测差异

## 1. 本次真实执行的对象与命令

- **旧版**：资料库 `claude-code-2.1.88-main(1).zip` 内的原 `cli.js`，使用 Node.js v22.16.0 运行。输出 `2.1.88 (Claude Code)`。
- **新版**：资料库 `claude-code-2.1.310-linux-x64.tar.gz` 内的原 `claude-2.1.310-linux-x64`，Linux x64 直接执行。输出 `2.1.310 (Claude Code)`。
- 两者均执行 `--version` 与 `--help` 并成功输出，**无需登录或真实模型 API 请求**；因此以下结果只说明 CLI 声明/参数入口的真实存在，不把完整运行链视作已实测。

```bash
node cli.js --version
node cli.js --help
./claude-2.1.310-linux-x64 --version
./claude-2.1.310-linux-x64 --help
```

本次按帮助文本中的**首选长参数名称**解析，旧版 **50 个选项、9 个顶层命令**，新版 **66 个选项、18 个顶层命令**：**新增 17 个选项，移除 1 个选项；新增 9 个顶层命令，未移除旧版顶层命令**。这些是 CLI 顶层帮助项目数，不能等同系统独立能力数，别名也未重复计数。

## 3. 新增的 9 个顶层命令

| 命令 | 2.1.310 最终帮助定义 |
|---|---|
| `attach <id|name>` | 将后台会话接回当前终端 |
| `gateway` | 管理企业认证/遥测网关 |
| `import [source]` | 导入其他 AI 编程代理配置 |
| `logs <id|name>` | 获取后台会话最近的终端输出 |
| `purge [path]` | 删除项目的本地 Claude Code 状态（会话、任务、历史、配置项），属于高风险动作 |
| `respawn [id]` | 用当前版本重启后台会话 |
| `rm <id>` | 删除后台会话，在安全情况下连同工作树清理 |
| `stop|kill <id>` | 停止后台会话并保留会话历史供继续 |
| `ultrareview [target]` | 通过云端多代理对当前分支/PR 进行代码审查 |

两版都存在的命令，例如 `agents`、`auth`、`auto-mode`、`doctor`、`install`、`mcp`、`plugin`、`setup-token`、`update`，其含义同样可能发生改变。新版 `agents` 的帮助改为**Manage background agents**，旧版为**List configured agents**；这可以直接看到用户操作定位的改变，不应只检查命令名是否还存在。

## 4. 相同选项中的实际语义变动

| 选项 | 2.1.88 的帮助 | 2.1.310 的帮助 | 升级要求 |
|---|---|---|---|
| `--permission-mode` | `default`、`auto`、`acceptEdits` 等 | `manual`、`auto`、`acceptEdits` 等 | 默认/别名/命令解析需按 2.1.200 后的 Manual 规范统一 |
| `--fallback-model` | 指定一个备用模型 | 接受**逗号分隔的多个**备用模型，按序尝试，每轮重试主模型 | 补多备用模型切换、故障与恢复 |
| `--agents` | 直接 JSON 对象 | JSON 对象，print 模式还可引用定义文件 | 补 headless 文件输入路径 |
| `--plugin-dir` | 目录路径 | 目录、ZIP、目录内批量插件 | 补来源/签名/权限/依赖处理 |
| `--print` | 说明跳过工作区信任对话框 | 同时强调无 TTY、无效设置的非交互处理 | 补无 TTY 安全状态/配置错误测试 |
| `--tools` | `default` 表示所有工具 | `default` 表示默认工具集合 | 按实际可用工具集区分显式全部与默认 |

## 5. 修订后的 CLI 升级优先级

1. **先对齐会话生命周期**：后台启动 `--bg` → `agents` 查看 → `attach/logs` → `stop/respawn/rm`；附加式命令需要共同会话状态和真实恢复规则。
2. **再对齐安全入口**：`--restricted`、`--safe-mode`、`--permission-prompts` 与 Manual/Auto 权限。必须验证工具隐藏、文件路径边界、策略来源和无用户回复的处理。
3. **再对齐模型/协议**：多重 fallback、系统提示快照、动态段分离、subagent stream-json、prompt_suggestion 事件。
4. **再对齐远程与扩展**：cloud/desktop/teleport/remote-control、plugin-url、gateway/import/ultrareview，并为需要账号或特定平台的能力标注条件。
5. **最后做逐入口真实验收**：新旧命令帮助内容可作为静态基线；会话工具、权限、错误和副作用必须运行实际测试。
