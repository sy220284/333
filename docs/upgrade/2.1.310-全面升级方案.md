## 1. 总体选择：以已构建主线进行终态差分升级，形成“单核心＋多入口＋能力插件”架构

比较了三条路径：

| 路线 | 优点 | 根本问题 | 决策 |
|---|---|---|---|
| A：保留最新 main 的 2.1.88 独立工程 | 三平台已有构建、发行及基础工具差分结果 | 尚缺目标 2.1.310 功能升级与专项验收 | **作为唯一开发底座，继承现有成果** |
| B：直接把 2.1.310 的 chunk 拼装成可运行版本 | 可观察部分新版行为 | Bun 虚拟路径、字节码、原生模块、条件配置和许可边界依然存在；难维护与测试 | 仅用于取证，不作为工程主干 |
| **C：在最新 main 上对照 2.1.310 终态逐能力升级** | 继承已验证构建和功能，按已有、待恢复、待重写精准处理 | 需完成版本差分、开关与代码调用链核验 | **采用；禁止重复建造或无依据地推翻旧工程** |

**技术栈候选（差分确权后定案）**：优先保持旧版已确认的接口和用户行为；TypeScript + Node.js 当前受支持的 LTS（实施时锁定具体版本）、pnpm workspace、明确的 ESM/tsconfig/build/test 配置；Ink/React TUI 单独包；高性能文件索引与音频/剪贴板等必要能力使用有源码可构建的原生适配层，可优先 Rust，但不能为了统一语言牺牲跨平台可用性。Bun 可作为经验证后的可选打包目标，不能作为源代码唯一路径。模型 API 实现为可替换适配器，保留 Claude 专有能力的独立实现，同时开放其他模型适配；绝不靠硬编码模型名称驱动通用流程。

           ▼
         Session Runtime

           │
      ┌────┼──────────┬──────────┐
      ▼    ▼          ▼          ▼
  Model   Policy    Tool Bus   Context/Memory
  Router  Engine    Registry   Store/Compactor
      │    │          │          │
      ▼    ▼          ▼          ▼

**结构性突破**：同一个 `capability-id` 绑定（1）新版源码证据，（2）旧版实现证据，（3）实现模块，（4）触发条件，（5）正负用例，（6）验收状态。后续版本只更新一次能力清单，自动生成测试覆盖清单和差异报告，消除每次从头梳理文件的重复劳动。

## 2. 在现有工程内建立职责边界（按需拆分）

**工程约束**：继续使用已验证的 `src/`、`native/`、`build/`、`tests/` 与三平台 CI。下述 `packages/*` 等是职责划分的规划路径；实施前不强制迁移目录。优先在现有代码中统一任务/事件、模型、工具、权限、持久化和 Agent/Workflow/Review 的边界，确有收益且全部回归成功后再抽取包。

| 组件 | 职责 | 明确边界 |
|---|---|---|
| `apps/cli` | 命令、参数、headless、输入输出格式与进程退出 | 不直接实现工具业务 |
| `apps/tui` | 聊天、权限弹窗、任务树、Diff、会话切换、键盘/语音 UI | UI 不直接发模型请求 |
| `packages/runtime` | 事件驱动的 Agent 循环、调度、状态快照、取消/重试/恢复 | 任何工具执行必须经过 policy |
| `packages/protocol` | 消息、内容块、工具调用、结构化流、事件来源类型 | 适配器之间统一语义 |
| `packages/providers` | Claude/其他模型请求、流式解码、限流、usage、缓存/重试 | 保留厂商扩展字段，通用核心不受制于厂商 |
| `packages/policy` | 硬阻止/明确授权/自动允许、数据目的地、来源防伪、安全审计 | 模型分类器不得直接授予执行权限 |
| `packages/tools` | Read/Write/Edit/Glob/Grep/Bash/Git/Notebook/Web/浏览器等 | 每个工具有 schema、权限、超时、撤销和负例测试 |
| `packages/workspace` | 工作树、路径边界、沙盒、文件变更、Diff 与回滚 | 区分本地项目与共享远程资源 |
| `packages/session` | 会话持久化、历史重放、压缩、备份、故障恢复 | 恢复不能伪造已完成动作 |
| `packages/context` | 项目指令、附件、提示词拼装、上下文窗口、缓存 | 用户指令/通知/外部材料分类型建模 |
| `packages/memory` | 记忆提取、召回、Dream 归并、过期核查 | 记忆不构成即时授权 |
| `packages/extensions` | MCP、技能、插件、Hook、扩展 API、兼容性验证 | 外部扩展最小权限和版本契约 |
| `packages/agents` | 可选协调者、Worker、Fork、Observer、子角色 | 默认单代理；用户明确授权才派生 |
| `packages/bridge` | IDE/远程/移动入口、WebSocket/SSE、重连/鉴权 | 网络来源与本地执行分离 |
| `packages/observability` | 事件追踪、资源统计、性能指标、脱敏日志 | 用户数据本地优先，遥测需明示与配置 |
| `native/` | 文件检索、图像、剪贴板、音频及其他平台能力 | 原生失败应报告具体不可用能力 |
| `tests/` | Mock/回放/参考行为差分/安全回归/端到端验收 | 验收记录可重复、可定位 |

当前 `src/` 与 `cli.js` 保留为**旧版行为基线**，逐项通过能力契约、最终源码证据与测试决定沿用、增强、替换或退场；禁止仅为架构整洁重写已满足终态的实现。新工程通过明确命名的目录补齐并接管。根目录仅保留标准元信息、workspace 配置、构建配置与项目入口，避免反复嵌套。

## 3. 核心功能升级决策

### 3.1 会话与模型执行核心（最高优先级）

- 基于统一状态机处理流式文字、思考块、工具请求、工具结果、部分 JSON、取消、续跑、重试、令牌计算和费用；工具结果必须与 tool-use ID 一一对应，避免丢块与重复执行。
- 每次有副作用的工具调用落盘记录 `request-id`、执行目标、批准人/批准来源、请求摘要、执行结果；进程重启时根据状态判定“未开始/已执行/结果未知”，未知状态先查证，杜绝重复写入、重复推送。
- 强制定义受支持模型的 capability profile（上下文窗口、流协议、思考块、图片、缓存、工具并发、结构化输出），用户可显式选模型，CLI/TUI/SDK 共用。
- 静态系统提示片段/动态上下文/项目指令/工具描述分开缓存。用回放检验模型输入顺序和来源。

### 3.2 工具与工作区

- 对已有工具逐项**保留并对齐最终语义**，按版本演进增加或调整 Read/Write/Edit/Glob/Grep、终端、Git、Notebook、Web、浏览器、PDF/图像、Monitor 等功能；不把旧版全部重建当成完成进展。2.1.277 已删除 TaskOutput，目标版本改由 Read 读后台任务输出文件。
- 对 Read→Edit、文件路径边界、二进制、编码、超大文件、软链、并发修改、沙盒与终端信号分别建立测试；不允许以“工具进程返回 0”冒充功能正确。
- Git 写入采用改动集隔离，检查当前分支、现有用户变更、Diff、测试结果后提交；只暂存当前任务所属文件；公共 PR 标题/正文按项目要求生成中文。

### 3.3 安全与执行授权（新版最关键结构升级）

新版 `permissions_external-df98b90a.txt` 中确认 **21 个环境配置字段、1 条 HARD BLOCK、72 条 SOFT BLOCK、17 条 ALLOW 例外**（顶层条目计数）；与 2.1.88 的 5/29/7 单层模板结构有显著差异。重建时建立可测试规则数据表与确定性 `PolicyDecision`，另用分类器辅助判断复杂语义。

必须覆盖：外部文本伪造用户指令；后台通知/定时触发/Worker 回报被当成用户同意；删除范围未知；敏感信息通过终端、浏览器、Git/CI、外部网络流出；越权执行；流水线绕过；共享资源操作；受保护基础设施变更。模型描述、记忆、工具输出不能提升自己的授权等级。

来源证据：`chunk-wany0nxw.js:520–554`（通知/定时标签）、`chunk-qg3fkqqr.js:64`（子代理回传）、`chunk-j0tbz6ra.js:52248,52435,52559,53142`（分类器及模板注入）。严禁简单复制庞大自然语言模板即宣称权限完成；规则须接上程序执行检查。

### 3.4 长任务、后台与多代理（按明确授权启用）

- 单代理默认可持续完成用户已授权且可恢复的工作；停机/额度/工具故障需记录剩余事项，恢复后先核对结果再继续，绝不承诺无法验证的后台进度。
- 工作树、临时目录、Git 分支/提交、工具进程和会话生命周期绑定；容器重启后旧进程状态变为“待核验”。参考 `chunk-j0tbz6ra.js:41825`、`chunk-4072fsq4.js:163`、`chunk-njrx31ky.js:85`。
- 协调者、Worker、Fork、Observer 分别定义角色、可用工具、写入空间、回传契约和失败交接；主代理必须独立验收 Diff/测试，不能直接信 Worker 自述；参考 `chunk-5qtb3hv4.js:99–320`、`chunk-f6dpayaf.js:34–73`、`chunk-28117reb.js:152–154`。
- **不默认启用派生代理，也不默认创建定时任务**。两者均必须有用户明确授权；定时任务来源也不得冒充实时授权。

### 3.5 上下文、自动记忆与主动交互

- 压缩须保留用户原话、不可变约束、操作已完成/未完成、文件位置、错误、待验收项和权限；恢复后按状态验证。参考 `chunk-j0tbz6ra.js:43349–43458`。
- 记忆类型分用户长期偏好、项目上下文和外部参考，过期信息以“待复核”标记；Dream 不自动改项目指令；参考 `chunk-d5zj5299.js:1822–1843`、`chunk-zsyd2kjt.js:48–105`。
- `/btw` 旧版已有；新版独立 “You should know”、一次性侧边提示、Artifact 评论读/写角色按触发条件接入，明确只读、一次性、无工具时不能声称修改；参考 `chunk-k9eem9n9.js:490`、`chunk-c910wjkr.js:124`、`chunk-8x7w052f.js:1833`。
- 用户可感知交互：结构化执行计划、正在运行/等待授权/已验证状态，Diff 预览，一键恢复会话，错误定位与可操作建议；中文/英文界面可切换。

### 3.6 扩展生态与接入

- MCP 的 stdio、SSE、HTTP/WebSocket 实际支持范围按协议适配并单独验收；插件、技能、Hooks 的加载、配置、卸载、权限、配置污染和版本兼容要有成对正负用例。

- 本方案 **只建立升级目标/工作路径**，不把 333 现有全部提取文件当作已完成新架构，也不把反编译 JS 行数当作功能数。
- 新版专用入口中部分带 feature flag、实验条件或平台限制，先登记再实测；未取得可触发条件的能力标注“待验证”，不能填“通过”。
- 用户未要求自动创建定时任务或派生子代理，本方案仅规划对应的可选能力，默认关闭。
- 最终的“完整交付”以可构建源码、完整用户功能链路和端到端证据共同判断。
