## 三、执行和复验结果

- PR #7 创建前研究库 `ASSESSMENT.md` 的“可研究、已编译、已实测”三种级别必须保留，不能以源码存在等同功能完成。
- 本次已经从现行主分支源码中清理 9 处 `src/cli/handlers/ant.js` 的旧引用、`TEMPLATES` 旧分发与 `VerifyPlanExecutionTool` / `OverflowTestTool` 注册。单独 CI `41411751934` 显示 TS 508→498、缺失契约 95→93；该次实测只证明旧入口修复，**不代表另 93 项完成**。
- 新增 `tools/governance/contract-trace.mjs` 的正式构建特性可达性检验：对可证明剔除的旧开关与内部用户分支另记 `excluded-by-build`，其余仍按“潜在可达”审查。可达性判定只服务于清理无效引用，不能替代 TypeScript 零错误门禁或新版运行验收。
- `research/` 中保存的 Computer Use/Chrome MCP 源码早于 PR #7，仅属于研究资料；目标版本的完整设备、浏览器、授权及状态/取消测试仍待实际闭环。
- 官方 2.1.310 的 102 项功能、84 场景、90 开关、61 条调用链和 6,313 条版本记录仍按原任务卡签收，不因本次旧代码清理减少范围。

## 四、后续修复顺序

1. **先修真实运行链**：Computer Use、浏览器 MCP、Monitor/Workflow、SDK 完整事件、上下文压缩与恢复。参考已有研究原文，逐消费者核对新版签名、权限、异常与用户可见效果。
2. **同时降低类型错误**：补真实缺失的消息/工具/任务契约；旧调用已退场的修改源调用，切断无效引用；不要引入无意义兜底和空模块。
3. **同版本验收**：执行官方 2.1.310 x64 与 PR #7 相同用例对照，三平台构建、质量门禁、SDK 消息、原生组件和资源哈希合格后才关单。

**维护方式：** 本文只记录已经取得的证据和实施决策。逐项需要从治理工作流的 `missing-contracts.json` 和 `missing-sources.json` 获取同一提交的实际数量，不能沿用上一个提交的数字。
