# 2.1.310 SDK 流事件与远程传输核验

## 已定位并修正的差异

- 新版 `chunk-bc0w6gb3.js:50-92,1388-1396` 仅在同一发送批次内合并连续且兼容的文本、工具输入 JSON、思考增量；不同块、父工具、API 响应、思考展示模式或中间事件均保持边界。合并大小按 JSON 转义后的 UTF-8 字节计算，超大临时事件跳过。旧实现跨批发送累计全文，接收端追加时会重复文字，也会破坏事件顺序。当前移植对应合并和大小限制，保留首条事件的 UUID 与其他字段。
- 新版 `chunk-j0tbz6ra.js:51512-51521` 与 `chunk-7rnqxvcm.js:4393` 将 API 响应 ID 和首字时间传给 SDK，并可携带思考显示、放弃的内容块和合并文本标记。当前从真实 `message_start` 跟踪 API 响应 ID，通过 SDK 输出和远程适配保留这些元数据；不凭空生成未发生的事件。
- 根据新版 `chunk-j0tbz6ra.js:47852-47874`，思考展示模式来自本次实际发出的请求，仅附在消息开始、思考块开始及思考增量上。当前已将实际请求中的 `thinking.display` 贯通至对应事件；显式配置和关闭思考分别由目标版 x64 和重建版的模拟 SSE 进行对照。
- 新版 `chunk-j0tbz6ra.js:51355-51357,51424` 在思考块开始时记时，结束时记录至少 1 毫秒的耗时和实际展示模式；`chunk-x3dkgs4r.js:711-712` 只在单个思考块的 SDK 助手消息中携带这两个字段。Actions `41538586609` 已验证目标 x64 和重建版在显式配置与关闭思考两种场景的消息字段一致，普通文本消息不带这些字段；19 项 Bun 回归通过。

## 证据及验收边界

- 从目标反编译源码直接抽取合并函数，覆盖 1,000 组随机输入，当前实现结果与目标函数逐项相同；另有事件顺序、跨批次、转义字节、超大包及字段往返的自动化回归。
- 以资料库 2.1.310 Linux x64 二进制和隔离本地 SSE 实测 print 模式：7 个事件顺序完整，两段文字依次为 `first` 与 ` second`，每个事件均带实际 API 消息 ID，首个事件带非负首字时间。`build/m1-sdk-stream-wire-parity.mjs` 以同一条件对照源码重建版；两者的实测结果以最新 CI 工件 `m1-sdk-stream-wire.json` 为准。
- Actions `41436787413` 已从源码重建并与固定哈希的官方 x64 实际对照：上述七事件、消息 ID 和首字时间均通过；显式 `summarized` 与关闭思考时的请求及事件字段分别通过。Bun 的 17 项协议、关闭与本地 HTTP 上传测试通过，实际上传的两批增量没有重复，事件边界保持顺序。
