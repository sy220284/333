# M1/M10 功能证据签收方式

截至本次 PR7 审计，**18 组源码升级工作**与**102 项功能、84 个 E/L 场景**分开统计。源码变更、静态接线、专项 CI、真实官方 x64 观察、全功能验收分别记录，避免用修改文件数或 CI 通过数替代完成度。

- 源码组：`PR7-18组功能链证据审计.json`，可以追加 G19、G20 等，不受初始 18 组限制。
- 能力契约与场景：`docs/upgrade/upgrade-coverage.json`，保持 102/84 起始覆盖。
- 正式签收：`PR7-M10-功能及场景签收.json`。仅在完成原版 2.1.317 x64 真实运行、反编译源码位置、重建版具体提交与成功 CI、独立的官方/重建/差分三份证据、审核人与时间、所有关联 E/L 场景后登记 `VERIFIED`。
- 证据注册器：`node build/m1-feature-evidence-registry.mjs --report <输出文件>`；正反校验：`node --test tests/m1-feature-evidence-registry.test.mjs`。

**本次原版与重建版四模式 PTY 专项已通过**：关闭、`--ax-screen-reader`、`CLAUDE_AX_SCREEN_READER=1` 和可信设置。证据见 GitHub Actions 41454253862；它证明启动状态的屏幕阅读器模式切换与终端控制序列减少，完整交互、工具、取消、恢复仍需实测，故 F001 尚不可正式关单。

签收器要求官方程序、重建程序、差分比较分别留存证据文件，防止同一份原版观察被重复引用冒充完整端到端验证。它会检查文件存在、签收目标、关联关系及签署信息；实际测试证据的真实性仍须由 CI 与审核人逐项核实。不得手动添加无证据的签收记录。
