- `Claude-Code-2.1.310-Linux-x64-跨语言高级代码补全验证版.tar.zst` 中 `reference/2.1.88-全量TS源码/src/` 的全部 **1,902** 个同路径项目源码文件。

## 逐文件一致性验证

以 zip 的 `source/src/` 为基准，相对路径与补全验证版的 `reference/2.1.88-全量TS源码/src/` 比较：

| 指标 | 实际结果 |
|---|---:|
| 原始 ZIP 项目源码 | 1,902 |
| 研究包中的 2.1.88 完整源码 | 1,902 |
| 两侧相对路径均匹配 | 1,902 |
| **字节完全一致** | **1,902** |
| 研究包新增的旧项目源码 | **0** |
| 研究包缺少的旧项目源码 | **0** |

再以 TypeScript 语法树核实旧版导入：186 个路径、658 处引用（433 处纯类型/225 处运行时）。原始 `cli.js.map` 的 4,756 条来源记录（均含 `sourcesContent`）没有对应这 186 条的独立完整原文。原始 ZIP 的 552 份内嵌 Source Map 可恢复各自所在文件的编译前代码，但不凭空包含这些独立的缺失模块。

**结论：研究包的「2.1.88 全量 TS 源码」是原始包的精确备份，而非能补出缺失 186 路径的新来源。** 不再针对这组重复源码反复进行同一轮全量搜索。

## 其他材料真实价值

跨语言补全验证版另有 56 份 TypeScript/TSX 文件，主要位于独立参考、源码/运行时高层实现、跨版本算法、重新编译主程序及测试目录。覆盖终端屏幕与 Bidi、Bash 解析、Yoga 布局、浏览器 native host、图像/剪贴板、文件索引等专项研究。

「基于 2.1.88 演进的高级语言实现」包只有 8 份 TypeScript 源码/测试，未找到消息协议、工具进度、会话选择、上下文折叠、缓存微压缩等目标缺失路径。

这两份研究成果中的补写实现必须与 2.1.310 **正式反编译 JavaScript 的真实入口、接口、结果和异常**交叉验证，再决定是否可迁入；不能由于包名包含「高级代码补全」便把研究代码视为厂商原始源码。

## 后续准确恢复路径

1. 从旧版消费方和内嵌原始 TS 签名，恢复 **type-only** 的消息/工具/向导等类型。
2. 从目标版正式 JS 追踪入口与实际消费者，确认 225 处旧版运行时缺失引用对应的功能，识别已转正、已合并、已退场或仍保留为内部条件能力的路径。
3. 对不可直接恢复但仍需实现的能力，按调用方的输入/输出、持久化、权限、失败与取消语义反推重写。
4. 继续以严格类型校验及原版/重建版真实运行差分决定验收，**不按文件数量或静态关键词签收**。

本文件属于 M1 源证据补全，不宣称 186 处路径已全部修复，也不推进 M2–M10。
