# 2.1.310 Linux x64 原版实机行为基准

核验日期：2026-11-02。对象为用户资料库 `claude-code-2.1.310-linux-x64.tar.gz` 内的 ELF x86_64 官方二进制（版本 `2.1.310`，SHA-256 `b73676430af12f97316a798b8371f81d640f90a58bdcb8f3ce56a835bb47df56`）。旧版对照是 333 main CI 运行 `41303439369` 的 `cli.js`（`dc505bf`）；升级分支对照是 PR #6 CI 运行 `41299616465` 的 `cli.js`（`5a45820`）。均已在 Linux x64 隔离 HOME 中实际启动。**此处结果来自二进制执行及真实本地 HTTP 请求，不把反编译关键词当成运行证据。**

**529 根因已定位并修复于 PR #6**：旧版 `withRetry.ts` 的计数/回退门控默认只对非自定义 Opus 生效；新版在用户明确传入备用模型时，对 Sonnet 也在连续三次 529 后切换。通过设置旧版隐藏变量 `FALLBACK_FOR_ALL_PRIMARY_MODELS=1` 的**诊断性对照**，PR #6 旧构建能重现官方 `3 → 3 → 1` 链，证实问题位于门控。PR #6 现已改为显式配置 `fallbackModel` 即可触发该计数，并完善去重/空项处理，不将测试隐藏开关用于正式产品。

PR #6 同时新增 `tests/fallback-529-integration.test.mjs`：使用本地 HTTP 529/SSE 固定响应检查模型实际请求序列，Linux CI 可下载 SHA 锁定的官方二进制运行双程序对照，Windows/macOS 对重建版本运行模拟链。与 2.1.310 原程序一致仅能在**最新 PR #6 完成 CI 后**作为正式签收。

## 参数差异与仍需重建的新版能力

经对两份实际 `--help` 进行规范化抽取，PR #6 旧构建仍缺这些新版标识（18 个标识，包括一个别名）：`--ax-screen-reader`、`--background` / `--bg`、`--cloud`、`--desktop`、`--environment`、`--exclude-dynamic-system-prompt-sections`、`--forward-subagent-text`、`--permission-prompt-tool`、`--permission-prompts`、`--plugin-url`、`--prompt-suggestions`、`--remote-control`、`--remote-control-session-name-prefix`、`--restricted`、`--safe-mode`、`--system-prompt-snapshot`、`--teleport`。PR #6 旧构建还保留官方新版已从帮助文本删除的 `--mcp-debug`。

这只确认 **CLI 表面缺口**，尚未证明这些能力内部没有其他入口。应按 M1 的 90 开关、61 新版能力和 6,313 更新逐条建立功能消费者，再决定 M2–M9 实施归属。

`--restricted` 新版帮助明确涉及三个独立环节：剔除执行命令/代码的工具及 WebFetch（显式 `--tools` 可例外），忽略非托管设置，限制文件工具的作用域。实测仅验证了 Bash 的工具列表变化；要实现完整功能，还必须做设置可信来源、权限及路径隔离测试。`--safe-mode` 需停用自定义配置来源，但保留托管策略和授权，不可和 `--bare` 等价处理。

另外，`--autocompact 1e6` 与 `--autocompact 200mb` 在官方 CLI 不会立即报参数错误，而 PR #6 的现有解析器拒绝；**尚未核实官方内部是否真正应用阈值或回退默认值**，必须进一步依据长上下文触发/调试证据确认，不能仅根据进入 API 请求就修改内部解析算法。

## 下一步严格关单

1. PR #6 最新代码必须在三系统真实编译并通过 529 / 多模型请求测试，包括 Linux 的 SHA256 锁定官方程序对照。
2. 参数层一致后，逐项核实会话、工具、权限、压缩、插件和电脑操作链；任何无法还原的源模块，以状态转移、错误/取消/恢复为重写和验收基准。
3. 主线保持 2.1.88 直到新版功能链全部验收，避免仅把版本号从 2.1.88 改为 2.1.310 造成虚假升级。
