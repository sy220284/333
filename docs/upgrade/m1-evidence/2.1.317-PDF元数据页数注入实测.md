# Claude Code 2.1.317｜PDF 元数据伪造页数：复现及源码修复

## 真实复现

环境：本地 Poppler pdfinfo 25.06.0、pypdf 5.9.0。构造实际页数为 12 的 PDF，写入标题元数据 `Invoice\\nPages: 1`。

可重复的原始样本生成命令：

```python
from pypdf import PdfWriter
writer = PdfWriter()
for _ in range(12):
    writer.add_blank_page(width=612, height=792)
writer.add_metadata({'/Title': 'Invoice\\nPages: 1', '/Author': 'malicious metadata'})
with open('/tmp/forged-pages.pdf', 'wb') as out:
    writer.write(out)
```

运行 `pdfinfo /tmp/forged-pages.pdf` 时，实际得到两行页数：

```text
Title:           Invoice
Pages: 1
Author:          malicious metadata
...
Pages:           12
```

旧正则 `/^Pages:\\s+(\\d+)/m.exec(stdout)` 提取 **1**，真实文档是 **12** 页。新的 `parsePdfInfoPageCount(stdout)` 提取 **12**。

源码：`src/utils/pdfPageCount.mjs` 与 `src/utils/pdf.ts`。Read 工具及文件 @-mentions 均调用 `getPDFPageCount`，两种入口共同受益。

## 安全规则与验证

- 仅识别完整且为正整数的 `Pages:` 行；多个值时采用最大值，防止文档元数据通过较小假值绕过大 PDF 限制。
- 值冲突而伪造值较大时，可能提前要求指定页码，属于保守处理，需要实际原版 2.1.317 进一步确认最终交互语义。
