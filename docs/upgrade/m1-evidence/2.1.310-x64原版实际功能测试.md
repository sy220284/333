## 三、模拟接口下的真实模型与工具调用

在隔离目录中起本机 HTTP 服务，使用固定模拟密钥（非真实帐号），令 `ANTHROPIC_BASE_URL=http://127.0.0.1:<随机端口>`。服务按 Anthropic Messages SSE 发送真实协议格式，原版 ELF 执行完整收发流程：

1. **单轮模型流式**：向 `POST /v1/messages?beta=true` 发起真实请求，模型/系统提示/用户消息正确进入 JSON；消费 `message_start/content_block_start/content_block_delta/content_block_stop/message_delta/message_stop`；最后返回固定文本 `M1_X64_LOCAL_STREAM_OK`、`terminal_reason=completed`、退出码 **0**。
2. **Read 工具往返**：模拟首轮 `stop_reason=tool_use`，指定 `Read` 读取本机测试文件；原版实际执行 `Read`，第二次 `/v1/messages` 请求携带 `tool_result` 和 `M1_READ_TOOL_FIXTURE_OK`，由模型模拟器发送最终文本，退出码 **0**。
3. **拒绝工具**：加入 `--disallowedTools=Read`，第一轮可用工具集合不再含 `Read`；即使模拟模型仍强行要求调用，第二轮上报 `is_error=true` 的 `tool_result`，**不泄漏文件内容**，随后终止，退出码 **0**。

这三项已经在当前工作容器里调用官方 ELF 实测。配套测试已提交 `tests/m1-x64-local-api.py` 并加入 M1 x64 CI 作业；**以该 CI 的新一轮结果为自动化复核证据**。

## 四、与 333 独立重建版的差分边界

从 **源码独立重建验证** 的 Ubuntu 作业 `41377680649` 获得 `rebuilt-claude-2.1.88-ubuntu-latest`（Artifact `13111682466`），实际检查包含独立 `cli.js`、`cli.js.map`、`launcher.cjs`、完整性清单与平台二进制资源。其说明仍标识 **2.1.88 来源重建**，启动需要 **Bun 1.4.4**；原版目标发行程序则是可直接执行的 2.1.310 x64 ELF。

此次已核验重建产物真实存在，**尚未拿到重建版按同一模型/工具协议的可执行差分成功证据**。该缺口不能由旧版三平台构建通过推定 2.1.310 行为已实现；下一步以固定原版和同一提交的重建版，在相同隔离目录、本机模拟 API、相同输入下比对 CLI 输出、工具结果、拒绝权限和状态恢复。

## 五、验收范围与剩余问题

原版实测给出确切升级基准，但不覆盖 OAuth 登录、真实云端 Provider、多 Agent 会话、外部 MCP/浏览器、交互式全屏终端与长时 Workflow。缺少凭据/授权的功能保留真实测试待签收，不用模拟结果冒充云端运行成功。

M1 的 90 种旧开关、61 项功能调用链、6,313 条变更语义仍须逐项闭环。PR #7 保持 Draft，M2–M10 继续冻结。本报告及测试器可在后续版本复用，替代反复手工比对。
