# M1｜第 0 层：构建基础

**目标版本**：Claude Code 2.1.317。
**改造范围**：官方资源、依赖、原生扩展、启动、独立构建和三平台发行。
**功能链**：C19；本卡拆分 5 个初始工作包。
**前置层**：无。
**实现状态**：进行中；本次更新任务范围与拆分，不把已有专项通过改写为整卡完成。

## 本卡执行要求

1. 以旧仓库实际生产调用链为改造对象，先定位新版入口、导入依赖、核心函数和全部消费者，再逐函数比较。
2. 对齐参数名称/类型/必填与可选/缺省及null语义、配置来源和优先级、功能开关、返回结构、事件顺序及错误码。
3. 对齐状态转移、权限、并发、超时、取消、重试、幂等、副作用、持久化和恢复；保留新版的能力启用和宿主条件。
4. 优先移植完整职责模块及依赖；有耦合则按职责拆分再接回生产调用链；缺失或不适配的实现按原版代码和x64行为重写。
5. 同包同步更新调用方/被调用方、组件、素材、提示词、技能、插件、接口schema、SDK类型、原生依赖及构建发行资源。
6. 已有且逐函数一致的代码保留；已完成专项沿用对应提交和测试，只补剩余差异。废弃逻辑按新版生命周期删除并同步迁移消费者。
7. 每包直接运行适用的功能与原版对照测试，覆盖成功、边界、错误、取消及恢复；只改入口、类型、开关或名称不足以完成工作包。
8. 当前137功能/137场景是已有回归范围，100个工作包是本轮拆分；新版调用链中新发现的函数、资源和能力继续纳入，不以这些数量限制升级范围。

原版位置以下以 `04_逐模块可阅读JavaScript/` 为默认根；资源目录单独列出。它们是本链已经定位的分析起点，实施时继续沿函数调用、导入和实际消费者展开，不限于列出的文件。

## 分链任务

### C19｜构建/资源/启动性能

**新版端到端调用链**：官方来源哈希 → 冻结依赖与技能恢复 → 独立构建 → 三平台/CI运行。

**新版分析起点**：`cli.js（新版主入口）`；`00_说明和核验/模块总清单.json`；`01_完整嵌入文件_原样/`；`02_解压文本与资源/`。

**旧仓库改造位置**：`build/rebuild.mjs`、`build/restore-claude-api.mjs`、`build/verify-bundled-assets.mjs`、`src/main.tsx`。

**当前差异与进度**：资源与Linux独立构建已有专项通过；三平台全部底层能力和正式发行链仍需逐项核对。

**关联链路**：C01、C03、C08、C09、C12、C13、C15。本链负责核心实现；关联链负责自己的入口、组件或宿主侧同步，同一实现不另设重复主责任。

**既有回归关联**：功能 F079；场景 E01、E26、E35、L27。以下任务同时覆盖新版新增能力，回归编号不构成范围上限。

#### C19-T01｜原版模块、资源和发行依赖盘点

- **代码任务**：沿cli启动入口、模块导入和原生装载展开新版依赖，核对旧仓库缺失、版本不同和旧包遗留项；补齐依赖并清理已被替换的装载路径。
- **同步更新**：内嵌文件、解压资源、第三方依赖、原生扩展、平台vendor与许可证。
- **完成检查**：目标版本、资源哈希、依赖锁和平台清单一致，缺失依赖能定位到实际消费者。
- **状态**：待逐函数差异核对及实施；已通过的相关专项作为保留基线继续使用。

#### C19-T02｜启动与能力装载顺序

- **代码任务**：移植配置初始化、功能开关、懒加载、收信服务和退出清理的新版顺序，拆开导入副作用，解决初始化循环。
- **同步更新**：entrypoint、setup、环境读取、错误展示及后台服务入口。
- **完成检查**：正常启动、帮助、非交互、显式服务失败和退出均有正确输出及退出码。
- **状态**：待逐函数差异核对及实施；已通过的相关专项作为保留基线继续使用。

#### C19-T03｜独立构建及资源解析

- **代码任务**：调整源码打包、文本资源导入、SDK声明生成和相对路径解析，保证每个被启用能力进入发行物。
- **同步更新**：build脚本、资源恢复器、声明文件、启动器及完整性清单。
- **完成检查**：在仓库外运行发行包，实际调用技能、文件工具与平台资源。
- **状态**：待逐函数差异核对及实施；已通过的相关专项作为保留基线继续使用。

#### C19-T04｜三平台底层能力装载

- **代码任务**：逐项对齐Linux/macOS/Windows的进程、终端、文件系统、原生扩展与权限接口；不能仅检查JS可编译。
- **同步更新**：平台vendor、Shell实现、原生模块入口、安装和升级路径。
- **完成检查**：三平台各自构建并运行适用能力；平台专有分支按原版可用条件验证。
- **状态**：待逐函数差异核对及实施；已通过的相关专项作为保留基线继续使用。

#### C19-T05｜构建回归与旧产物清理

- **代码任务**：统一源码到发行物的执行路径，移除不再参与运行的旧引用，检查冷启动与错误恢复成本。
- **同步更新**：CI触发、缓存键、发布清单、干净安装和版本显示。
- **完成检查**：同一提交的资源、构建、独立启动和异常测试通过，旧依赖不再被误加载。
- **状态**：待逐函数差异核对及实施；已通过的相关专项作为保留基线继续使用。

**本链闭环条件**：本链五个工作包及实施中新发现的适用能力均完成；真实入口、底层执行、关联组件/资源、接口双方和异常恢复达到原版语义并通过测试后再标记整链完成。

## 整卡完成条件

1. 本卡全部功能链和工作包，以及执行中新发现的适用新版能力，均已在仓库实际生产代码中落实。
2. 功能实现、底层能力、参数、行为逻辑、语义、接口、组件和资源同步；调用链从用户/SDK/服务入口贯通到执行和结果。
3. 需要修改的依赖已移植、拆分或重写；与新版一致的旧代码保留并验证，旧的重复执行路径及废弃关联已清理。
4. 成功、错误、取消、并发、重试和恢复等适用场景通过；平台或远程宿主所需的接口双方及真实运行已验证。存在未实现或未验证分支时保持进行中。
5. 完成后复查本卡及跨卡关联，再执行整仓审计与回归，修复遗漏；构建通过或静态命中不单独作为整卡完成依据。
