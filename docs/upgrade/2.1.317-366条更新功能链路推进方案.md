## 具体执行办法

1. **原版取证**：每个官方条目从 2.1.317 可读源码、内嵌资源和原始 x64 中提取行为与真实入口。功能受限于企业/云端宿主时同时记录该部分真实服务端证据。
2. **全链扫描**：沿“输入或触发 → 策略与参数 → 实际执行/异常/取消 → 状态持久化 → 消费者和显示”检查 333 的实际实现。跨链共享的权限、模型、会话状态和插件发现逻辑优先修复根因。
3. **迁入或重写**：有完整官方源码则优先移植；原版代码缺失时，根据 x64 真实请求、响应、状态、副作用和失败分支实现。相邻链依赖一起测试，避免移植后没有入口。
4. **版本差分**：每条以官方原版和 333 重建版同参数测试，保留 SHA、目标平台、脚本、日志及具体判定；再检查 Linux/macOS/Windows 和必要的 IDE/Remote/企业云应用。
5. **单条关单**：只有官方证据、源码关联、成功/失败用例、端到端副作用和跨端覆盖都通过，才能由 `PENDING_SOURCE_BINARY_E2E` 调整为正式签收；完成总数始终按 366 逐条核查。
