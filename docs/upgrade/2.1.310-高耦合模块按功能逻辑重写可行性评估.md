# 333：2.1.310 高耦合模块按功能逻辑重写的技术可行性

**分析对象**：2.1.88 Source Map 提取的 TypeScript 主体与 2.1.310 Linux x64 全量可读 JavaScript。对应 333 的 M1–M10 十张执行任务卡；**不新增、删除或重新排序任务卡，也不缩减 102 项功能和 84 个验收场景**。

**以最新 main 校正实施起点（2026-11-01）**：333 已从 2.1.88 的 `src/` 完成独立 Bun 构建、三平台发行/基础工具差分，并建立 `research/claude-code-2.1.88/` 研究索引。因此本文件的“重写”专指 **新版目标仍需、且既有实现不能直接复用的功能逻辑**；优先升级现有 Query/Agent/工具/权限等代码。执行细则以[总方案](./2.1.310-全面升级方案.md)和[单独缺口文档](./2.1.310-升级缺口与逐项核查清单.md)为准。

## 最终技术判断

**高耦合部分适合按功能逻辑重写，优先选择完整行为契约 + 独立实现。** 大部分本地功能具有可观察入口、请求/输出协议和部分可读实现。跨平台/外部服务功能需要补协议适配与真实环境验收。云端私有能力只有客户端控制逻辑在本地包中，无法直接从客户端恢复服务端实现；可以做可用的等效功能，算法质量须用缺陷样本等实际证据证明。

**技术路线**：保留 2.1.310 原程序作行为参照；旧版有实质 TypeScript 的功能优先在旧实现上升级；高耦合 Bun JS 按实际执行路径提炼行为合同，在独立的任务、权限、模型、工作区内核上逐功能重写；旧/新共用验收库。原生可独立加载的纯函数按需直接复用。

## 静态依赖与重写价值

- 2.1.310 顶层 **2,550** 个可读 JS 文件，总计约 **58.99 MB**。上一轮按所有 BunFS JS 字面引用计算的 Workflow 传递依赖 **1,335**、Review **1,399**、CLI **2,542**，属于静态可达候选范围，**不是各功能真实运行必需文件数**。
- 按编译模块内**静态 ESM import** 独立扫描得到另一统计口径：Workflow 直接识别 **84**、Review **90**、CLI **7** 条模块依赖，包含动态加载/虚拟文件系统的源代码意味着该口径不能覆盖完整运行链。把两种数混用会高估或低估迁移量。
- 2.1.310 的大量模块保留 `/$bunfs/root/` 引用，核心代码出现资源管理语法 `using`、`import.meta.require` 和原生模块装载。重写业务逻辑可以免去模拟整套 Bun 打包资源环境，但还要重建功能本身所用的授权、存储、并发和外部协议。
- 2.1.88 的 TypeScript 提取树已有较实质的实现：`src/QueryEngine.ts` **1,295 行**，`src/query.ts` **1,729 行**，`src/services/api/claude.ts` **3,419 行**；`src/tools/AgentTool/runAgent.ts` **973 行**，`src/tools/shared/spawnMultiAgent.ts` **1,093 行**，`src/utils/permissions/yoloClassifier.ts` **1,495 行**，`src/cli/structuredIO.ts` **859 行**。这些旧源码已经进入可独立编译的 333 主线；**当前已验证工程构建和基础工具，不能据此推断每一分支功能都已通过真实调用验收**，仍应核查七个缺失模块及未启用功能开关。
- 新版 `chunk-2pjf4p7s.js` **1,764 行**可读 Workflow 调度逻辑；`chunk-n7dvjfwp.js` **2,769 行**含本地审查与入口选择；`chunk-j0tbz6ra.js` **90,902 行**聚合大量主程序逻辑，适合按职责提炼，**不适合把巨型文件逐行翻译为一个巨型新文件**。

## 重写可行性分级

| 领域 | 可重写性 | 可直接复原的要素 | 必须独立解决的要素 | 判定 |
|---|---|---|---|---|
| 模型请求、流式事件与 Query 循环 | **高** | 旧 TypeScript 请求/重试/流解析/工具 ID；新版参数、模型能力、流格式 | 不同模型厂商的工具/schema/思考/缓存能力；API 错误和分段失效 | 适合直接按协议/状态机重写；输出内容不能逐字要求相同 |
| 文件、搜索、Bash、Git、Notebook 等工具 | **高** | 工具 schema、输入校验、成功/失败、取消与输出截断 | 沙盒、进程树、编码、平台差异、原子写入 | 适合独立工具总线，避免搬运通用依赖 |
| 权限规则、自动模式及来源隔离 | **高，安全验收难** | 规则模板、分类器提示/旧代码、许可/拒绝场景 | 程序侧强制执行、用户批准来源、网络出口与沙盒边界 | 可重写，所有拒绝/升级权限负例必须真实通过 |
| 会话/任务持久化、压缩和恢复 | **中高，可靠性风险高** | 旧任务/会话结构、新版状态提示与 journal 行为 | 崩溃窗口、幂等键、未知副作用、跨版本数据、完整回放 | 采用事务日志 + 外部动作核实，不机械复制旧日志吞错行为 |
| 多 Agent、Coordinator/Worker/Fork | **高** | 旧版本地 spawn/runAgent/LocalAgentTask；新版并发、审批、结构化结果校验 | 角色权限交集、冲突隔离、取消、模型继承和输出归属 | 复用旧逻辑，统一任务引擎后可实现新版用户行为 |
| 本地 Workflow | **高，调度恢复复杂** | 新版 `agent/parallel/pipeline/workflow`、脚本隔离、预算、schema 和日志 | 脚本确定性、嵌套限制、资源上限、审批与可重复恢复 | 有足够可读算法支撑重写；重点投入故障注入验证 |
| 本地 `/code-review` | **高** | 新版等级/参数解析、审查角度、发现协议、`--fix`、`--comment` | Git Diff 范围、模型差异、错误路径、只读/写入授权 | 先按目标版本重写本地审查，再叠加深审 |
| 云 Ultra 级深度审查 | **等效重做中高；私有服务端精准复刻低** | 客户端调用、上传/回传/发布、部分普通 Review 配方 | 云 BugHunter 内部调度、独立验证算法、置信度/质量校准不在客户端包 | 本地建独立发现—验证—反证—去重—报告，验收以召回/误报/复现为准 |
| CLI/headless/SDK/协议 | **高** | 真实命令帮助、结构化事件、已有旧版 CLI/SDK 实现 | 新版入口差分、退出码、跨入口同一会话/任务结果 | 优先实现可复现机器协议，UI/远端共同消费 |
| TUI、IDE/远程、桌面/移动 | **中高** | 命令/事件/界面行为、旧 UI TypeScript | 终端渲染、输入焦点、连接鉴权、跨系统平台实现 | TUI 本地可重写；外部桌面/移动配套需相应客户端或桥接器 |
| 插件、技能、MCP、Hook、Mods | **中高** | 各扩展入口和部分事件/Hook/Schema | 插件 ABI/协议兼容、发现、升级、运行隔离、外部插件行为 | 可重写宿主；兼容性须拿真实扩展做回归 |
| 语音、剪贴板、浏览器/原生功能 | **中等，平台敏感** | 装载接口、部分原有音频/浏览器/图像处理 | `audio-capture.node`、`clipboard-napi.node` 等二进制/OS 接口未包含在可读 JS；权限与平台环境 | 用受支持 OS API/独立驱动重做，需 Windows/macOS/Linux 各自实测 |
| 云账号、云环境、远端 Agent、配额和同步 | **客户端重写高；服务端精准还原低** | 本地入口、云请求/结果协议、错误和会话生命周期 | 远端服务能力、认证与配额策略、账号数据、服务端实现 | 可写可替代 provider/backend；不能声明与未取得的服务器完全一致 |

**“高”表示有足够实现依据、无明显算法不可得问题，不表示代码现成或测试已通过。** 工程量应按依赖、正确性与外部服务而非原 JS 文件行数计算。

## 关键代码证据与可还原契约

### 本地 Workflow

`chunk-2pjf4p7s.js:480–530` 包含 `agent/parallel/pipeline/workflow` 入口；约第 319 行建立确定性脚本环境（拒绝无参系统时间与随机数）；第 512 行对子 Workflow 的嵌套层数施加限制；第 828–831 行具备 Agent 调用上限（错误里明确 cap=1000）；第 955–968 行对 `disallowedTools` 和 `bashCommandClamp` 做强校验并拒绝不合法请求；约第 1056 行要求合法可用的 JSON Schema。

约第 988–1005 行显示 journal 的 started/failed/result 记录逻辑；追加失败可仅记录 warning，结果无法序列化也可能导致恢复后重复执行。**重写应保留用户可见的续跑语义，同时在新底座中强化可落盘状态检查，副作用不确定时先对账，避免重复写入/发布。**

第 1007–1008 行有本地路径明确拒绝 `isolation:'remote'`，第 1425–1448 行另有远端执行分支。两条路径应根据真实构建/入口条件单独验收，不能统称新版本缺少远端 Agent。

可行的最小独立实现组成：脚本解析及沙盒、步骤依赖调度、Agent 接口、模型 schema 验证、权限拦截、并发与预算、持久化 journal、恢复及不确定副作用核实。**一个 Workflow 引擎即可被 Review 调用**。

### 新版本地代码审查和本地深审

旧版 `src/commands/review.ts:9–43` 只是简单 `/review` Prompt。新版 `chunk-n7dvjfwp.js:1050–1193` 定义多种审查配方，其中部分明确要求在当前上下文完成多个 finder angle、`dedup only (no verify)`、`do NOT spawn subagents`。第 1250–1271 行解析 `--max-findings`、`--fix`、`--comment`、努力等级和目标；约第 1340–1395 行包含 Ultra 不可用时**告知原因后回退本地普通审查**的行为。

这使本地基础 Review 的逻辑重写可行性很高：原代码内已有用户入口、参数、Prompt、输出和可见回退行为。**多 Agent 独立验证属于另外的深审功能**：需要 Git 快照与跨文件调用链、多个独立角度、可复现测试、反例核对、去重/证据汇总，不能将普通本地 Review 的候选清单直接宣称为云 Ultra 水平。

云端 BugHunter 完整服务端算法未包含在本机发行包。对其输出质量只能通过缺陷样本库、同条件模型和真实运行的召回、误报、复现率等指标证明等效程度。

### 多 Agent 与权限

2.1.88 `src/tools/AgentTool/runAgent.ts`、`src/tools/shared/spawnMultiAgent.ts`、`src/coordinator/coordinatorMode.ts`、`src/tasks/LocalAgentTask/LocalAgentTask.tsx` 提供可读的本地代理、协作及任务基础。2.1.310 Workflow `chunk-2pjf4p7s.js:955–1086` 清楚表现出失败即拒绝的参数权限校验与代理创建前检查，适宜转化为强类型输入、程序级阻止规则与可重放负例。

并行代理都必须共享统一任务事实与工具授权；不能仅因模型输出建议启动另一个 Agent 就自动授权。派生代理与定时任务保持默认不触发。

### 模型、会话与工具

旧版 `src/services/api/claude.ts`、`src/query.ts`、`src/QueryEngine.ts` 已有流式协议和模型工具循环的明确实现基础；新版需要逐功能核对不同提供商、结构化输出、重试、缓存、取消和事件排序。重写时应将模型能力声明与实际可调用操作挂钩，缺少 schema/tool-use 能力时明确拒绝。

文件与系统工具可以依据公开的 OS、Git、语言工具链能力重做；真正高风险的部分是权限、命令取消后的进程清理、覆盖已有未提交改动以及执行成功后日志丢失。**这些都能通过受控样本、故障注入和真实文件结果验证**。

## 独立重写架构：功能接口替代编译模块依赖

`CLI/TUI/SDK/IDE → 统一协议 → 任务/权限/工作区/Provider → 工具/Agent/Workflow/Review → 持久化事件与结果`。

- **共享一次**：`Task/Run/Step` IDs、权限判定、模型能力、事件序列、资源预算、快照与日志。
- **分别实现**：工具执行器、Agent 工作器、Workflow 调度器、审查/验证器、各平台 UI/Bridge。
- **一个审查核心**：普通本地 Review 与 Ultra 级深审共用 Git 采样、发现协议与模型调用；深审扩展独立验证和反证。
- **替换方式**：原版程序仅作为行为对照/必要时的临时进程适配器；高耦合模块直接按目标行为重写到独立核心，避免为了迁移旧 Bun 编译文件维护第二套运行系统。
- **语言路径**：333 旧版为大量 TypeScript，若目标是尽快恢复全功能且后续重做，TypeScript/Node 主核心能利用旧接口与工具生态，减少一次性依赖适配；若未来选择其他实现语言，先固定事件/权限/工作流/审查的语言无关协议。

## 验证方式与验收门槛

采用原有 **F001–F102、E01–E68、L01–L16** 台账作为验收来源；无需增设执行任务编号。

每个重写功能至少提供：

- **行为签名**：输入、输出/事件、失败/退出码、权限条件、平台条件、调用侧效果、可取消/可恢复状态。
- **参考测试**：能由原版执行的场景与新实现同条件对照；模型自然语言文本允许波动，工具调用 ID 对应、状态序列、权限与文件结果必须一致。
- **异常测试**：无效参数、无权限、断网、超时、磁盘满、进程崩溃、重试、资源回收和并发冲突。
- **外部服务边界**：无本地服务端算法时以用户可见行为和独立质量测试为准，明确不可证明的内部等同性，不编造已复原程度。
- **签收要求**：代码实际可构建，相关 E/L 正反例通过，有日志和产物，才可进入已完成状态。

## 最终建议

**无需先让高耦合的编译 JS 在 333 内跑通再重写。** 直接建立统一的任务、模型、工具、权限和事件核心；从旧版 TypeScript 继承已验证逻辑，以 2.1.310 可读 JS 的实际执行路径补齐新版差异。原版二进制只承担参考/必要时临时兼容角色。多 Agent 和 Workflow 都具有较高的逻辑重写可行性；本地普通审查同样较高；云 Ultra 的深审质量应单独作为基于证据的重建目标。
