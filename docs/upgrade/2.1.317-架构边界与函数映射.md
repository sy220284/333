# 2.1.317 六层架构边界与原版函数映射

基准：官方 Linux x64 2.1.317 反编译包 `04_逐模块可阅读JavaScript/`。实施分支：PR #7。该文档记录真实入口和责任边界，缺口按 M1→M6 任务卡原顺序处置；所有功能必须经过行为验证后才结案。

## 真实运行方向

原生 Bun 可执行程序 → CLI 快速分流及交互唯一模式检查 → REPL 交互入口 → query 推理循环 → 工具装配、权限与 Hooks → Agent、后台执行、插件/MCP → 会话存储与交互界面。MCP、Runner 和内部工作进程保留专用启动入口，为交互工作提供服务。

## 本轮落地的 M1 结构调整

- 官方 `cli.js` 在引入常规 CLI 前分流 `plugin test`，分为独立测试程序及单文件 worker。PR #7 原先仅在 `src/main.tsx` 的 Commander 中注册，调用时需要先经过普通主程序入口。
- 已在 `src/entrypoints/cli.tsx` 添加 `plugin test` 的合法参数快速分流，具体解析与策略/处理器调用由 `src/entrypoints/pluginTestFastPath317.ts` 负责；其他命令仍由原有主入口接管。
- 复用既有 `pluginTestHandler317` 执行真实测试与文件隔离，避免引入第二套测试执行器。`tests/m1-plugin-test-fastpath-317.test.mjs` 通过编译后 CLI 子进程验证帮助、越界文件拒绝及正常目录错误，并接入三平台 `rebuild.yml`。
- 原版 `chunk-jsb8d11a.js` 的 `pluginTestGatesOf` 包含实验开关状态与设置持久化；本轮接入专用启动和组织版本策略，实验开关的完整原版等价继续由 M3 C11/M5 C09 验收。任何阶段均不据此标记 M1 整卡完成。

## 不变的验收规则

1. 每个改动以原版函数、所在入口、所有调用者与相应资源为依据；旧实现已经一致时继续保留。
2. 必须用编译后真实入口跑成功、错误、权限、取消、清理、恢复场景，并在 Linux/macOS/Windows 适用平台执行；文件存在或类型检查通过只能证明局部条件。
3. 整卡完成以全部工作包和新发现的关联能力达成原版行为一致为前提，按 M1→M2→M3→M4→M5→M6 顺序推进。
