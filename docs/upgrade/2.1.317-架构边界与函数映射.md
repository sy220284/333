# 2.1.317 六层架构边界与原版函数映射

基准：官方 Linux x64 2.1.317 反编译包 `04_逐模块可阅读JavaScript/`。实施分支：PR #7。该文档记录真实入口和责任边界，缺口按 M1→M6 任务卡原顺序处置；所有功能必须经过行为验证后才结案。

## 真实运行方向

原生 Bun 可执行程序 → CLI 快速分流 → REPL / SDK / Headless / Runner 入口 → 统一 query 推理循环 → 工具装配、权限与 Hooks → Agent、后台执行、插件/MCP → 会话存储与远程输出。

## 本轮落地的 M1 结构调整

- 官方 `cli.js` 在引入常规 CLI 前分流 `plugin test`，分为独立测试程序及单文件 worker。PR #7 原先仅在 `src/main.tsx` 的 Commander 中注册，调用时需要先经过普通主程序入口。
- 已在 `src/entrypoints/cli.tsx` 添加 `plugin test` 的合法参数快速分流，具体解析与策略/处理器调用由 `src/entrypoints/pluginTestFastPath317.ts` 负责；其他命令仍由原有主入口接管。
- 复用既有 `pluginTestHandler317` 执行真实测试与文件隔离，避免引入第二套测试执行器。`tests/m1-plugin-test-fastpath-317.test.mjs` 通过编译后 CLI 子进程验证帮助、越界文件拒绝及正常目录错误，并接入三平台 `rebuild.yml`。
- 原版 `chunk-jsb8d11a.js` 的 `pluginTestGatesOf` 包含实验开关状态与设置持久化；本轮接入专用启动和组织版本策略，实验开关的完整原版等价继续由 M3 C11/M5 C09 验收。任何阶段均不据此标记 M1 整卡完成。

## 不变的验收规则

1. 每个改动以原版函数、所在入口、所有调用者与相应资源为依据；旧实现已经一致时继续保留。
2. 必须用编译后真实入口跑成功、错误、权限、取消、清理、恢复场景，并在 Linux/macOS/Windows 适用平台执行；文件存在或类型检查通过只能证明局部条件。
3. 整卡完成以全部工作包和新发现的关联能力达成原版行为一致为前提，按 M1→M2→M3→M4→M5→M6 顺序推进。

- 已修改 `src/utils/config.ts` 显式保存全局配置文件监听器归属，接管时取消旧文件监视并清除旧文件缓存。MDM 原始预读与 Keychain 预读各提供跨会话重置入口，避免旧预读 Promise 在新环境下重新写入缓存。
- 实际结果以 `tests/m1-claim-rebind-317.test.mjs` 的跨目录/配置切换与 `tests/m1-preload-317.test.mjs`、`tests/m1-bg-spare-317.test.mjs` 真实进程行为及同提交三平台 CI 为准。此项完成后仍需对照原版 Runner Storage V5 后端、policy helper 及后台宿主条件，M1 整卡维持进行中。

### M1 Storage V5 预热身份与目录重绑定（2026-11-05）

- 原实现 `getProjectDir` 通过 lodash memoize 只按工作目录缓存，`getTranscriptPath()` 又记忆当前会话的文件归属。预热进程接管新的 `CLAUDE_CONFIG_DIR` 时，即使环境、配置、证书缓存已清空，同一工作目录的缓存仍可能指向先前配置根目录。
- 新增 `rebindSessionStorageForClaim317()`：先等待旧 Project 写入完成，再重置会话写入对象、项目路径缓存、Storage V5 的身份路径映射，并绑定当前已接管的会话身份和目录；由共享 `claimRebind317.ts` 执行，覆盖 `--preload` 与 `--bg-spare` 两条生产链路。
- 回归用例使用实际两套配置根目录和同一工作目录制造旧缓存，验证重新接管后的项目路径、JSONL 归属；同时验证映射清空、重绑定。相关测试原已接入 `rebuild.yml`，需以新提交三平台实际验收为依据。
