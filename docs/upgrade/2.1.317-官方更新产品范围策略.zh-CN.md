# 2.1.317 官方更新的独立产品验收口径

## 结论与范围

本仓库以官方 2.1.317 反编译行为为主要对照基准，同时遵守独立产品的现有架构与本地化要求。官方 2.1.311–2.1.317 发布台账 **392 条**全部追踪；当前产品逐条适用范围以以下文件为**唯一判定来源**：

- 官方原文：`docs/upgrade/m1-evidence/2.1.311-2.1.317-官方逐条变更与验收台账.json`
- 完整更新矩阵：`docs/upgrade/m1-evidence/2.1.317-392项完整功能链路分组矩阵.json`
- 产品范围：`docs/upgrade/m1-evidence/2.1.317-392项产品保留适配与退役判定.json`
- 验收契约：`tests/upgrade-317-coverage.test.mjs`

目前的范围判定为：

| 类别 | 项数 | 处理与验收 |
| --- | ---: | --- |
| 保留原版行为 `RETAIN_OFFICIAL_PARITY` | 221 | 逐项核验 2.1.317 源码与实际输入输出、异常、审批、中断、恢复及跨入口一致性 |
| 适配独立本地架构 `ADAPT_TO_LOCAL_EQUIVALENT` | 76 | 保留用户可观察的关键行为和安全保证，按本地/独立服务商新接口验证；官方仅作为行为依据 |
| 已退役的官方专属能力 `EXCLUDE_RETIRED_FEATURE` | 95 | 不再作为功能实现或原版云端回归的合格条件；验收退役入口、隐私与网络边界，不允许重引入官方云服务 |
| **官方来源完整追踪** | **392** | 每条保存原文、ID、版本和功能链，源头覆盖始终为 392/392 |

这三个数字属于**产品范围分类**，绝不等于通过了相应数量的运行测试。原版详细矩阵保留原有验证状态；产品签收须另有实际执行证据。

## 保留与适配的执行原则

1. **保留的核心能力**：工具调用、权限沙箱、SDK 控制、Hooks、文件/PDF、Agent 事件、模型调用、MCP、命令执行等，检查与 2.1.317 原版在可观察结果上的一致性。
2. **多模型体系**：Claude 已保留的功能按原版行为，OpenAI/ChatGPT、DeepSeek、Qwen、Kimi、GLM、MiniMax 根据各供应商能力与原生 API 规范适配，重点检查参数缺省、推理档位、工具往返、异常/取消和费用。已退役 Gemini、xAI/Grok、OpenRouter 相关入口不恢复。
3. **本地 SDK 与会话**：官方云会话相关的权限、安全、会话重复提交、任务中断和错误回传等通用规则，在 `src/services/conversation/`、`src/services/desktop/`、`desktop/` 中按等效效果验收；不连接官方 Remote Control 或 Anthropic 会话云。
4. **MCP 表单与链接**：云端的 MCP elicitation 通用语义仍适用于本地宿主，按 `hostControlBroker.ts` 及 `sessionRuntime317.ts` 的实际控制请求/回执测试。官方云客户端卡片样式不在验收范围。
5. **代码审查与反馈**：旧 `ultrareview` 及原厂云审查变为统一 `/review`、通用 GitHub 审查；原厂反馈上传变为 `/feedback` 本地报告文件。检查用户入口、输出结果、权限、错误、离线可用性及隐私。
6. **长期任务与调度**：云端托管的 `/schedule`、云 Routines 和官方 self-hosted runner 不恢复；本地工作项与恢复按授权的主动启动、队列生命周期、人工复核、任务簿和异常恢复验收。

## 退役功能的检查边界

- 官方 Claude Tag/Slack 频道机器人、企业管理卡、云定时/例行任务、Remote Control 和云端工作区/runner 只验证其原厂入口退役且无意外的网络回传。
- OTLP/OpenTelemetry 云端遥测、Anthropic 管理后台统计及 IdP 分组上传退出产品功能验收；仍要求本地诊断保持隐私、失败可见与存储限制。
- 官方云技能/设计同步、Claude 专属订阅升级和原厂云环境配置退役；本地插件、凭证、模型能力目录与 GitHub 通用工作流继续独立验收。
- 对于一条官方更新同时提及云端场景与可复用的本地安全/恢复语义，优先采用“本地等效适配”，不能因为例子来自云端就丢失核心行为。

## 执行与验证方法

```bash
node --test tests/upgrade-317-coverage.test.mjs
node --test tests/independent-product-cleanup.test.mjs
```

基本 CI 将运行覆盖检查，独立产品专项门禁继续检查退役的官方命令与网络上报是否重新出现。

**正式签收标准**：保留项需原版差分；适配项需本地端到端路径及异常恢复；退役项需入口清理/隐私保护的可验证记录。任何新官方更新都必须先补产品范围判定，然后进入对应代码验收。源文件仍按原始功能链 C01–C20 记录；不可将“已退役”误记为“已实现”。

当前上述 392 项的产品范围已分类，但完整功能测试与跨平台 CI 结论仍必须依据对应最新提交的实际运行结果出具。
