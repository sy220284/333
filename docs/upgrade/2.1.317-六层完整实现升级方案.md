# 333｜Claude Code 2.1.317 完整代码与底层能力对齐方案

## 目标与范围

将 PR #7 中旧版代码，完整升级到官方 Claude Code 2.1.317 各条功能链的代码实现和底层能力。对照新版入口、函数及依赖、状态与接口，处理旧实现差异，采用保留、整体移植、职责拆分、调整、重写和旧逻辑清理，使功能实现、行为逻辑、语义、参数、返回、异常及恢复保持对齐。

每项改造同时覆盖相关调用者和被调用者、组件、素材、提示词、技能、插件、接口双方、SDK类型、原生能力、依赖及构建发行资源。完成的是生产调用链从入口到执行、结果和恢复的整体更新。

目标范围以新版实际能力及其启用条件为准，包括正式功能开关、宿主限制和平台差异。已有137项功能、137个场景用作回归索引；它们和本轮100个工作包均不限制进一步发现的新版函数、能力与关联资源。新版移除或替换的旧能力，按新版处理其入口、迁移和消费者。

## 执行单位：一张任务卡

- **“完成一项”专指完成一张 M1–M6 任务卡**。Cxx 功能链、Cxx-Txx 工作包、原生资源专项和独立测试都是卡内实施与验收证据，不单独计为“一项完成”。
- **严格串行**：先完成 M1 的五个工作包及其所有新增关联缺口，源码、真实发行包、官方原版行为、三平台适用能力和异常恢复全部达到本卡完成条件，复查通过后才进入 M2；之后按 M2→M3→M4→M5→M6 同样执行。
- **状态以整卡验收为准**：卡内某些专项或 CI 通过，仅记录为已验证的局部证据；任何必需调用链、宿主或回归尚未验证，整张卡保持“进行中”。修复失败项后继续复测、清理旧实现与跨卡接口，不通过统计已完成子项数量推定整卡完成。
- **每张卡实际闭环后自动衔接下一张**：完成整卡复查，更新卡片状态及 PR #7 进度，立即沿顺序处理下一卡，不要求用户反复下达继续指令。

## 按新版代码展开任务

1. **从新版真实实现出发。** 读取完整反编译模块、内嵌资源和官方x64，定位入口、能力条件、导入依赖、核心函数、事件与实际消费者。卡片所列模块是已经定位的分析起点，继续沿调用关系展开，避免以搜索命中替代函数分析。
2. **比较旧仓库的整条链。** 对照代码实现、参数和默认值、状态转移、权限、持久化及资源生命周期。逐项判断保留、移植、拆分、调整、重写或删除，并明确需要一起修改的关联端。
3. **优先移植完整职责模块。** 同步带入依赖、协议和资源，接通生产入口。新版模块与旧架构耦合方式不同，先按职责拆分旧实现，再连接完整消费者。源码缺失或无法直接适配时，依据新版已知代码和x64真实输入、输出、状态及副作用重写。
4. **同步参数与语义。** 核对名称、类型、枚举、必填/可选、缺省/null/空值、配置来源及优先级、开关、返回结构、错误码、事件顺序、并发、取消、超时、重试、幂等和恢复。界面中文适配保留，同时保持协议和执行语义对齐。
5. **同步所有关联部分。** 更新界面组件及状态、图标/动画/背景等素材、提示词和技能正文及脚本、插件运行时和包结构、MCP/SDK/IDE/远程/云接口双方、原生扩展、依赖锁与发行清单。
6. **直接运行并修复。** 覆盖成功、边界、错误、取消、并发和恢复，比较原版与重建版输出、状态和副作用；适用时执行三平台和真实宿主测试。已有专项通过沿用对应实现和回归，继续补剩余差异，不重复重做已经核实的代码。
7. **完成整链再更新状态。** 所有工作包、关联端及新增发现的能力都落实并验证后，才把功能链和对应卡片标为完成。当前更新的是任务要求与拆分，实际产品实现仍按代码进度推进。

## 当前差异对任务的约束

已完成部分模型目录/effort、读取边界、会话身份、Shell环境、MCP认证和purge文件清理等修正。这些属于可保留的专项基线，六张卡仍需逐函数完成剩余调用链。

当前明确缺口包括 gateway、ultrareview，插件 details/eval/init/prune/tag/test、命令哈希授权、部分函数式插件UI/媒体接口、组织连接器/文件服务和企业Runner能力。IDE、桌面/移动与外部服务还需匹配版本的接口及宿主侧同步。已存在的模块也必须核对实际实现和消费者，不能按“有同名文件”判定对齐。

## 完成后复查与全仓审计

先复查每条链的全部工作包和关联接口，再检查跨链组合：模型到请求、权限到真实副作用、Hook到SDK回执、代理到存储恢复、插件到UI/MCP、附件到模型/远程、企业身份到网关/Runner，以及外部事件到结果投递。

全仓审计包含旧版遗留执行路径、重复实现、失效参数与类型、未使用或缺失资源、能力开关、依赖和平台分支，并核对错误、取消、并发、重试、数据迁移、恢复及资源回收。发现缺口直接归回原责任链修复并复测。构建通过、静态命中、单元测试或模拟通过分别用于对应范围，整卡完成还需要其实际调用链和适用宿主验证通过。

任务、进度和必要测试结果沿用现有文件维护，直接推进代码修复；不新增人工签收、多层证明或重复报告步骤。
