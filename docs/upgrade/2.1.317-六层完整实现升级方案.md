# 333｜Claude Code 2.1.317 全功能实现六层升级方案

**唯一实施目标**：将 333 现有 TypeScript/Bun 工程按官方 Claude Code 2.1.317 的完整源码、资源、函数语义与用户可观察行为升级，直至所有适用功能链的入口、调用者、权限、执行、状态、输出、异常和恢复闭合。优先移植官方真实实现；源码不足时追踪原版 x64 运行行为，以真实输入输出、事件和状态证据进行语义重写，并接通上下游。

**当前任务体系只有 M1–M6 六张卡，逐层对应 20 条完整功能链。** 原 M1–M10 的旧任务归属、分工、关单口径退出执行。完整功能链是新的验收对象，既有 F001–F102 / E01–E68 / L01–L16 回归只用于防止历史功能损失；发现新的官方功能、分支或消费者应加入对应链，并新增测试。

## 每一条链的真实交付流程

1. **目标实现取证**：锁定官方 2.1.317 安装包 SHA、反编译可读函数/模块、内嵌资源及事件接口，记录原始路径、函数入参/返回/内部状态/分支/调用者，连同缺失处一并标注。若 2.1.317 的真实函数已有新版替代，沿替代实现而非旧名称迁移。
2. **现有调用链核查**：从 333 的入口向执行器、持久化、权限、SDK/CLI/UI/插件及错误恢复追踪所有生产者与消费者；核实真实可达条件和同一功能的冗余实现。逐项对照函数语义、数据结构、消息顺序和异常结果。
3. **代码迁移优先**：可得到原始可读代码的部分直接移植、消除重复实现、补齐依赖和版本资源；有源码缺失时先复原调用和状态图，再用官方 2.1.317 Linux x64 安装包真实运行、模拟 API/工具副作用与 PTY/进程测试捕捉目标行为，依据证据完整重写。不得用固定返回、空壳和静默容错宣称实现。
4. **覆盖各种分支**：至少验证成功、权限拒绝、参数异常、超时取消、重试/断连、边界数据、并发与恢复；适用时验证 Linux/macOS/Windows、终端动画、SDK 消息、官方技能资源字节与原生扩展。
5. **跨层、跨宿主验收**：逐链执行官方原版和候选版的同条件测试，比较事件、状态、输出/副作用和异常；IDE/企业云/Remote Control/Slack 等需要真实宿主/服务端或可独立核实的原始外部协议证据。
6. **签收与回归**：每条链存放目标函数锚点、实现提交、独立成功/失败用例、x64 原版日志、候选日志、差分、CI 和评审签名。依赖层的真实功能链通过且消费者不回归后才能签收整层。未取得完整证据保留待核状态并继续修复。

## 机器数据和证据边界

- [20 条新版完整功能链与六层归属](2.1.317-六层完整功能链路.json)：新版实施唯一任务源。各条源码路径目前是**待核候选**，引用不代表已经成功移植。
- [历史功能与场景基线](2.1.317-功能与场景源数据.json)：保证 102 项功能/84 场景不遗失；可扩展，不形成新版能力上限。
- [生成的实现覆盖快照](upgrade-coverage.json)：每条 F 编号都有所属主功能链和 M1–M6 责任，校验 6 层/20 链及既有回归。
- [20 条功能链正式签收](2.1.317-功能链路签收.json)：只有真实代码和运行证据齐全方可 VERIFIED。
- [旧有 102/84 功能与场景签收](2.1.317-功能与场景签收.json)：作为回归和消费者签收，仍以官方 2.1.317 为目标；完成其中一项不自动签收整条功能链。
- [六层签收规则](2.1.317-验收规则.md)：严格检查同环境运行、事件/状态语义、外部宿主要求与被影响消费者。

**两条工作线分开**：本方案只管理官方 2.1.317 的完整功能实现及行为语义移植，不接管、统计、关闭另一条“366 条版本更新专项”。该专项原有文件、编号、分组、更新数和进度继续独立维护。对本方案而言，20 条链和六层全部验证才构成完成。

**本次改动是执行体系重构**：旧任务口径退出，已有产品源码修复、真实测试及历史证据仍需在新六层下复用和复核，不能据此提前标记功能已完成。
