# M1：旧版缺失源码与类型定义的双版本核查（2026-11-01）

## 核查范围与结论

本轮直接读取用户资料库的 `claude-code-2.1.88-main(1).zip`、其 `cli.js.map`（4,756 个源码映射记录）和 `Claude-Code-2.1.310-Linux-x64-完整反编译包.tar.zst`。另外交叉读取 333 M1 分支和类型治理 PR #9 的源文件。

**三个层次必须分清**：

- 旧版原始项目中缺少文件：静态扫查旧版 `source/src` 的相对模块导入，得到 **188 个候选缺口路径、660 处引用**，包含类型、运行模块、开关内的编译期死分支。扫描为正则索引，尚未通过每个条件分支的 TypeScript 类型解析，不等于 188 个都应写回当前产品。
- 旧版 Source Map 无法直接提供原文：逐个检索 `types/message`、`types/tools`、`keybindings/types`、`constants/querySource` 以及原登记的七类模块，`sources` 与 `sourcesContent` 中都无这些原始路径。尤其 TS 类型在编译时擦除，**不能因为 JavaScript 反编译可读就推断原类型可提取**。
- **2.1.310 的真实执行语义必须独立确认**：同名关键词或相近输出不代表同等能力；只有得到实际入口、分支和结果的证据才改变终态。

本次 188/660 是旧源码归档的缺口搜索基线，并非 PR #7 最新可执行分支的精确 TS2307 数量。当前治理 PR #9 的正式类型基线为 1,786 条诊断、其中 TS2307 为 787 条；两个统计口径不可相加。

## 类型定义：从高影响缺口追根因

旧版 `src/types/message.js` 约 163 处相对引用（最大缺口），承担用户/助手/系统消息、工具回调、进度消息、压缩边界和事件类型。这是**横跨消息协议的总约束**，简单写成 `any` 会直接抹掉错误检查，不允许。

其次，`src/types/tools.js` 约 18 处相对引用，涉及 Bash、PowerShell、Agent、MCP、Skill、TaskOutput、WebSearch 的进度数据及 SDK 工作流事件；`src/keybindings/types.js` 约 17 处；`src/constants/querySource.js` 约 16 处。这些都是有真实消费者的类型契约，优先按调用者的属性读写、联合值和入参返回值推导，再通过 TS 类型检查和实际行为回归签收。

**与 PR #9 的工作分界**：PR #9 已新增 `src/constants/querySource.ts`、`src/keybindings/types.ts`、`src/components/Spinner/types.ts` 等按消费者还原的具体类型，并已有 `tools/governance/missing-sources.mjs` 和 `contract-trace.mjs` 收集 TS2307、导入符号和运行/纯类型区别。应直接复用 PR #9 的类型治理结果；M1 维护双版本最终语义和版本任务承接，避免在两个 PR 对同一个类型文件做冲突的独立实现。

## 恢复与重写的明确决策

1. **旧版或新版本来有完整原文，且接口相同**：先验证来源 SHA/内容、真实调用方及行为，再原样恢复；不补假类型。
2. **目标版语义已明确变化**：按实际目标版处理。例如快照入口固定保留 keep，不再创建已退场的更新弹窗。
3. **原始类型已被编译器擦除**：根据旧源码与新版 JS 的调用者、函数参数/返回对象、SDK 类型、状态机事件逐步重建；先处理类型流入最多的消息/工具协议，再做类型和三系统运行回归。
4. **源码消失但正式功能依然需要**：从依赖引用追查输入、输出、状态、权限、安全边界、异常/取消/恢复路径，编写可执行的功能重建和双版本差分用例。禁止空文件、`any`、静默忽略和“仅使构建通过”的替身。
5. **目标版确认退场且旧代码未正常启用**：移除真实无效的旧依赖并记录证据，避免为了凑齐历史文件恢复已删除的实验功能。

M1 尚未达到三项全量终态验收：90 开关、61 项入口与 6,313 条更新仍须独立完结。此文件记录源证据和可恢复路径，不将类型治理 PR #9 的未合并改动或新旧关键词匹配算作 M1 完成。
