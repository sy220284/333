## 本次已改进的根因

1. 旧 `providerFields.ts` 遇到 Kimi K2 强制指定工具时，静默改成 `auto`，违背调用者的强约束；现在明确拒绝并告知其能力限制。
2. 旧能力探测器对 DeepSeek 默认思考模式和 Kimi K2 强制指定测试工具，与上述服务商参数冲突；现在探测使用这些模型接受的 `auto`，仍要求实际两轮工具结果闭环。
3. 加入 DeepSeek/Kimi 双轮工具策略回归，修复最新 `multimodel-provider.test.ts` 的跨平台 lint 失败。
4. 供应商 SSE 必须携带稳定工具 ID；此前为缺失 ID 生成随机 ID 可能让第二轮工具回执无法配对。现已统一拒绝，并添加两协议负例测试。
5. 对 DeepSeek 上游请求的 `x-deepseek-request-id` 进行安全归一，保留服务商诊断与限流提示，同时继续遮盖凭证。
6. 按 Codex 的工作区身份区分，同一 ChatGPT 用户下不同 `chatgpt_account_id` 的模型缓存和推理续接各自隔离。验证 ID Token 后才读取工作区声明。
7. ChatGPT SDK 客户端每次请求和 401 刷新时重新取得磁盘账号状态，和最初绑定的用户/工作区比较；退出或切换账号后，旧客户端直接拒绝调用。

## 下一个真实验收门槛

- 以上更改的当前提交必须完成模型协议、开发质量、类型检查、三平台构建、MCP v2 的 GitHub Actions 检查；失败要继续修复。
- 在用户已授权的真实供应商模型上进行：工具调用→权限/Hook→执行→第二轮工具结果→恢复和结束事件；按模型、账号、失败类型记录证据。
- ChatGPT OAuth 的 `api.openai.com/v1` 资源与 Codex 的 `chatgpt.com/backend-api/codex` 账号端点拥有不同的身份/授权约束。首先验证当前授予的 token audience、scope 和 account ID，再决定是否添加独立 Codex 账号适配入口，避免将一个端点的令牌误送另一个服务。
- 每条 C01-C20 链按成功/拒绝/取消/异常/恢复验收，官方 317 的保留能力与 333 独立替换的能力分别记录，通过后才写正式签收。
