# PR19 智能体用户体验、稳定性与部署验收记录

审计日期：2026-11-07。对象：摇摇车 PR19，主子智能体模式与 Super Agents 协作模式。此文件是**持续验收清单**，所有最终通过结论应以相应提交 SHA 的真实测试记录为准。

## 用户希望完成的整条路径

1. 安装并打开 Electron，确认桌面 Host 真正连接；切换智能体和长期任务页面
2. 创建一个长期目标，立刻看见目标、任务 ID 和选中状态
3. 给目标添加工作项，确认持久存储、没有暗中调用模型
4. 暂停、恢复目标，记录检查点，重开页面仍能找到进度
5. 在明确授权下启动单项或多项任务，遵守同 Mission 最多三个运行项的限制
6. 每个工作项保留会话、权限申请、工具输出、执行历史；结果进入待审核
7. 人工检查交付物后批准、要求重试或中断；重启后核对副作用再恢复
8. 创建团队、成员通信、认领任务、离开团队和清理资源；多个项目互相隔离

## 已定位并修复的实际问题

| 严重度 | 现象 | 根因与处理 |

## 从使用者角度的评价

**主子智能体模式**：任务委派、后台执行、停止与恢复可复用现有 AgentTool 及 Workflow，适合明确且可验收的开发工作。关键体验是分工容易，但恢复必须保留原代码隔离边界。

**Super Agents 模式**：具备 Mission、持久工作项、Team 消息和共享状态、最长三项并行、用户授权持续派发、结果人工审核。适合“分析→实现→复核”长期项目。当前使用方式仍偏专业控制台：用户要自己写标题和完整指令，Bot 角色/职责模板、成果验收摘要和团队创建向导还不够直观。

**值得继续投入的方向**：让新手在界面中选一个目标，选择“调查/开发/验证”任务模板后自动生成待确认的工作项和分工；每个任务自动关联测试记录、变更差异、实际耗费和最小可读总结。保留人工启动、权限审核与一键停止。

## 仍需实施或实测的关键边界

1. **并行改同一个项目**：跨独立 Mission Job 目前使用同一工作目录。AgentTool 有显式 Git Worktree 能力，但 Mission Job 缺少强制的逐项工作树创建、文件冲突审查和合并入口。多项并行代码修改有互相覆盖风险；在该路径端到端验收前，应将它视为高优先级工程缺口
2. **全局资源预算**：已限制单个 Mission 同时三个工作项，但不同 Mission/多个宿主之间尚缺共同的 CPU/模型预算总上限；需要统一配额与可中断调度
3. **审批后的交付验证**：目前以会话总结和人工审核为主，缺少按任务关联的 Git diff、测试证据和明确合并按钮
4. **运行边界**：连续派发只在用户明确启动且本地桌面宿主存活时推进。关闭后不自动恢复或创建定时任务；这符合当前本地化与授权策略
5. **正式可用性证明**：要求最新 SHA 的安装版用户操作测试通过、开发质量门禁没有新增问题、恢复与中断测试通过；再进行具有真实授权的模型实网样本验证

## 验收标准

功能是否完成以实际调用结果判定：能创建 → 能执行 → 能停下 → 能恢复 → 能查看结果 → 能确认交付。团队链路需要再证明：能建队 → 能发消息 → 能认领任务 → 能退出与清理。每项保留对应源码、测试名、提交 SHA 和 GitHub Actions 运行 ID，防止把只编译成功误报为用户功能可用。
