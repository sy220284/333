# DeepSeek Harness Android · 前后台分层与三级导航交互设计方案

**版本：V1.1｜2026-11-12｜产品状态：已实现并验证的 HTML 交互原型／Android 原生实施规范**  
设计基准：`deepseek-ai/deepseek-harness` 的既有完整功能解析，沿用 V1.0 的 71 项功能映射；结合此前使用的设计技能 V2.4 中移动优先、单列主任务、原生触控与因果动效原则。

## 1. 本轮的产品决策

**日常使用只看到任务、项目、历史、能力与设置；后台机制自动运行，并把必要的状态反馈显示在用户正在做的事旁边。**

V1.0 的主要问题是把 71 个功能页面几乎等同于侧栏菜单：用户需要理解工具、存储、运行时、协议和诊断才能找到要操作的地方；主任务与配置项同等抢占注意力。V1.1 调整为：

- **6 个一级导航**：开始、会话历史、工作区、运行中心、能力中心、设置。能力中心是新增的导航聚合页，不是新增的 Harness 核心功能。
- **菜单最大三级**：一级领域主页 → 二级功能 → 三级对象详情；允许从搜索或任务结果直接跳转到二、三级，返回原任务；弹层不是第四级菜单。
- **71 项原功能逐一归属**：5 项原有一级入口 + 27 项二级功能 + 18 项对象详情 + 15 项任务内按需操作 + 6 项后台能力。另加 1 项导航聚合页，原型共 72 个注册页面/定义；真实用户一级菜单依然只有 6 项。
- **系统能力按需显露**：正常时呈现处理结果；用户要作决定时呈现权限范围和审批；任务失败时显示可复核的原因；开发人员需要调查时才进入日志、诊断和完整配置。
- **交互由结果与任务驱动**：浏览器/MCP/模型能力是否可用来自当前环境的真实状态；原型是本地模拟，不虚构已连接的后端环境。

### 谁应该看见什么

| 类别 | 典型功能 | 产品处理 | 普通用户看到 |
|---|---|---|---|
| 日常主导航 | 会话、项目、运行、能力、设置 | 固定侧栏 6 入口 | 去做某件事的明确入口 |
| 功能页 | 文件、PR、模型、技能、工具连接、计划 | 从对应领域进入，作为第 2 层 | 本领域常用操作与简明状态 |
| 对象详情 | 文件编辑、Diff 审阅、MCP 服务、插件详情 | 从具体对象进入，最高第 3 层 | 单个对象的内容、状态和必要动作 |
| 任务内操作 | 操作授权、用户追问、代码跳转、文档转换、语音、分享 | 会话内卡片、文件工具条、底部弹层、专用全屏详情 | 操作发生时才出现，完成后自动返回原上下文 |
| 后台自动 | 网页搜索工具、内部翻译、自动审查、SDK/ACP、事件钩子、遥测 | 不设独立的日常菜单项 | 搜索结果、译文、审核结论、运行状态或诊断摘要 |

## 2. 菜单结构：最多三级

“层级”按**实际需要经过的菜单主页**计算。列表中可以查看对象或打开操作弹层，但不得再出现第 4 级目录。由任务内操作产生的弹层保持原页面，不消耗一个菜单层级。

```text
侧栏 · 一级（6 项）
├── 开始
│   └── 当前会话（2）       ← 输入、结果、执行信息入口
├── 会话历史
│   ├── 全局查找（2）       ← 也可从顶部/侧栏搜索直接打开
│   └── 会话信息（2）       ← 会话归档、恢复、所属项目
├── 工作区
│   ├── 项目文件（2）
│   │   ├── 文件预览（3）
│   │   ├── 文件编辑（3）
│   │   └── 文件搜索（3）
│   ├── 文件改动（2）
│   │   └── 代码审阅（3）
│   ├── Pull Request（2）
│   └── 独立工作树（2，Git 可用时）
├── 运行中心
│   ├── 当前任务详情（2）
│   ├── 执行轨迹（2）
│   ├── 后台任务（2）
│   ├── Agent 团队（2）
│   │   ├── 子智能体（3）
│   │   └── 共享任务板（3）
│   ├── 工作流 / 持续目标 / 计划（2）
│   └── 交互终端（2，检测可用性后提供）
├── 能力中心
│   ├── 技能（2） → 技能详情（3）
│   ├── 插件中心（2） → 插件详情 / 发现 / 创建（3）
│   ├── MCP 工具连接（2） → 服务详情（3）
│   ├── 浏览器操作 / 设备操作（2）
│   └── 自动化任务（2） → 创建或编辑计划（3，显式发起）
└── 设置
    ├── 模型选择（2） → 服务配置（3）
    ├── 账户（2） → 凭据管理（3）
    ├── 执行权限（2）
    ├── 外观与交互（2）
    ├── 核心环境（2） → 远程环境（3）
    ├── 问题诊断（2） → 性能分析（3）
    ├── 使用统计（2）
    └── 反馈（2）
```

**特殊情况**：对象详情也可能直接由所属领域打开，例如历史 → 会话信息、运行中心 → 当前任务详情，两者是两层路径。V1.1 数据表据实标为 2 级，避免为了凑满三级虚设“中转页面”。

### 侧栏展开时具体显示

顶部为“新建任务”和“搜索任务、文件和功能”；其下是上述 6 个一级入口，每项一行功能解释；最下方为最近两项任务与诊断/设置入口。侧栏**不罗列工具名、MCP 资源、原始 API、SDK、钩子和一大串技术参数**。

侧栏搜索只索引可进入的功能页及其详细对象页，搜索到三层页时可直接打开，顶部仍显示真实的领域路径。后台自动模块仅在运行轨迹或诊断信息里可被看到。输入框、搜索和运行胶囊都是交互捷径，不增加一层菜单。

### 返回与并列切换

- 任务正在进行时，从对话进入审批、文件、运行过程和配置，返回时保留任务草稿与阅读位置；用户也可直接使用“回到任务”。
- 第三级文件详情内“编辑/预览/搜索”之间切换属于**同级对象操作**；不再产生第 4 层目录。
- 系统返回优先关闭键盘和最上层弹层，其次返回来源页面；侧栏收起后原页面保持。Android 版应支持系统预测返回手势。
- 每个页面都能点击左上角回到六入口侧栏；完成一次用户操作后，显示具体结果，等待授权的提醒同步消失。

## 3. 后台能力与 UI 的职责分界

划分原则：**需要用户选择目标、理解结果或承担决定的功能必须有界面；无需用户介入的执行机制放在后台；出问题时在对应任务里提供完整可追溯证据。**

| 后台功能簇 | 后台负责什么 | UI 的正确反馈位置 |
|---|---|---|
| Agent 循环、上下文、系统提示词 | 读取上下文、请求模型、调度工具、整理执行轮次 | 对话的流式回答、运行胶囊与执行时间线 |
| 模型路由、重试、令牌计量 | 选择已配置模型、执行请求、重试、统计 tokens | 输入框的模型选择；账户用量与运行详情；失败时给出明确原因 |
| Node PTC、原生工具执行器、Shell/Subprocess | 调用模型选用的工具并受约束执行 | 时间线的“命令执行”事件；用户主动进入时才显示交互终端 |
| 沙箱隔离、授权规则、自动审查 | 判定读写范围、必要时阻断操作或发起审批 | 会话内权限标签、审批单、执行状态；完整规则进高级诊断 |
| 会话事件、日志、JSON/SQLite 存储 | 保留消息、操作与结构化事件 | 会话历史、任务恢复、执行记录；存储引擎细节放在后台 |
| 历史压缩、文件附件、Spill 与超长结果裁剪 | 自动压缩上下文、整理附件、控制结果大小 | 仅在发生时显示“上下文已整理”“输出可展开/下载”；不单设菜单 |
| 文件搜索索引、LSP、Web 搜索 | 在任务中检索文件、代码符号或网页来源 | 文件搜索结果、代码“查找定义/引用”、对话内来源引用 |
| 插件注册、MCP 会话与服务管理 | 发现能力、维护连接、调用工具/资源 | “能力中心”状态和连接详情；只有增删改连接需用户操作 |
| 凭据刷新、身份信息与平台证明 | 安全管理密钥、刷新令牌或完成平台认证 | “账户/连接状态”；失效时引导重连，不能要求填原始 token JSON |
| SDK/ACP、Webhook Hook、遥测 | 服务接入、事件分发、脱敏诊断 | 管理入口收于“自动化/诊断/隐私”，普通任务中无独立 SDK 面板 |

**六项原功能明确归入后台自动**：网页搜索（web-search）、内容翻译（translation）、自动审查（auto-review）、SDK 与 ACP（sdk）、事件钩子（hooks）、日志与遥测（telemetry）。它们在 v1.1 的一级导航和侧栏功能搜索中全部隐藏，但可通过相关任务状态、结果、技术详情或权限设置查看影响。

### 十五项改为任务内按需交互

| 能力 | 触发位置 | 交互方案 |
|---|---|---|
| 操作授权（approval） | 会话提醒／运行中心待确认 | 必须展示对象、范围、完整命令和允许/拒绝，处理后更新状态 |
| 追问（questions） | 当前任务回复 | 问题卡／答案选项，不作为独立导航页 |
| 单次执行（command） | 任务轨迹里相应步骤 | 查看命令、退出码、输出、停止情况；主动终端独立可进 |
| 代码定位（lsp） | 文件/代码区域 | “跳转定义、查找引用、实现、悬停说明”；后端未连接则解释原因 |
| 语音输入（voice） | 对话输入区麦克风 | 授权录音 → 转写 → 写入可编辑草稿 → 用户决定发送 |
| 会话分享（live-share） | 会话更多操作 | 权限范围选择和可撤销授权；按环境开关可用性 |
| 应用授权（app-grants） | 电脑操作步骤 | 对具体应用/窗口/动作授权，随调用按需出现 |
| 文档转换（office） | Word/Excel/PPT 的文件操作 | 预览、转 PDF、格式导出、表格公式重算；按类型显示 |
| 文档预览（document-preview） | 文件预览内 | 按文件类型切换渲染器，保持当前文件与路径 |
| 运行检查（inspector） | 诊断的技术详情 | 仅在诊断时查看，不上主菜单 |
| 原始日志（logs） | 失败步骤或诊断详情 | 按事件展开完整记录，支持复制脱敏内容 |
| MCP 资源（mcp-resources） | 具体 MCP 服务详情 | 在服务下查看资源及模板，不与 MCP 连接并列一级 |
| Ralph 迭代（ralph） | 工作流启用迭代后 | 展示轮次、上限、交接信息；默认不占独立入口 |
| Todo 清单（todo） | Agent 团队与任务过程 | 任务状态附着到正在执行的工作，不另设独立主页 |
| Webhook（webhook） | 用户主动管理自动化 | 外部事件来源、权限、验签与状态属于计划的详细选项 |

## 4. 六个一级页面的实际展示

### 4.1 开始页：任务画布

首先看到当前项目与正在执行的任务；主要文案“今天，继续推进什么？”直接把注意力引到输入。已有任务展示一个“继续工作”的重点对象，最近记录仅两三行。底部输入区保留附件、模型、权限、语音和发送按钮。运行状态只有任务正在执行时出现。**不设计系统参数仪表盘或 71 张功能卡。**

### 4.2 会话历史：找回工作

按最近使用和工作区排列；入口只负责“继续、查找、归档、会话信息”。搜索结果定位原对象；工具细节由打开会话后的时间线提供。

### 4.3 工作区：材料与交付

优先显示当前工作区，文件、代码改动和 PR 为三个核心动作。Git 工作树归入折叠的高级操作。代码 Diff 在窄屏单列逐文件展示；预览、编辑与 LSP 使用文件上下文。Office 转换必须识别文件格式：示例 Kotlin 源码不会展示“转 Word/PDF”，示例 DOCX/XLSX 才会出现转换与重算操作。

### 4.4 运行中心：执行状态与决策

顶部展示等待用户决定的事项；中部显示正在执行任务、执行轨迹与后台作业；团队、长目标、计划和终端按需展开。状态依次可以是：准备、运行、等待授权、等待回答、恢复、已完成、失败、停止中、已停止。真实停止完成须以核心回执为准。

### 4.5 能力中心：先用途再扩展

首先是技能、插件、MCP 工具连接；其次是浏览器和设备操作；定时/事件任务折叠。页面避免“内置能力已经存在却要求用户手动填一大堆参数”的体验：先发现/探测可用能力，缺失认证或服务条件时再展示必要的设置向导。Android 本机不支持的桌面自动化需要明确提示连接可用宿主。

### 4.6 设置：日常少、排障深

默认只有模型、账号、外观和执行权限；运行环境、诊断和使用统计折叠。SDK、通信协议、原始日志和遥测属于高级诊断信息，不把它们当成普通设置表单。成功变更以核心确认后刷新真实有效值；错误需显示修改失败原因并保持此前生效状态。

## 5. 核心操作闭环

### 发送与审批

1. 输入任务，可以附加图片/文档、选择模型和权限；发送后草稿在收到真实确认前保留。
2. Agent 后台处理上下文、检索、工具执行和模型回复；界面只显示“当前步骤/结果摘要”。
3. 需要人工决定时，运行胶囊和当前会话出现“待确认”；用户打开完整命令、文件范围后作出决定。
4. 审批提交中防止重复操作；收到后端决定回执后，审批状态变为已允许或已拒绝，待确认提醒消失；任务继续或终止。
5. 完成显示回答、文件成果、改动与验证结果；若测试未跑，应写“未验证”。断线恢复先重读会话事件与待决定队列。

**V1.1 原型已模拟**允许/拒绝后的反馈与提醒消失。它不会向 Harness 发起真实工具授权。

### 插件与 MCP

能力中心 → MCP 连接（第二级）→ 某服务详情（第三级）；资源、凭据与状态在当前服务详情按需展开。后台资源模板不成为菜单项。安装插件时先展示提供的能力、权限与版本，再进入安装、更新和启停的状态闭环。来源、认证和可用工具数量来自服务回执。

### 文档操作

工作区 → 文件 → 预览：代码文件显示编辑和符号跳转；DOCX、XLSX、PPTX 文件显示对应预览、转换、重算或导出。保存/转换失败应保留输入草稿与原文件，返回具体错误而非静默成功。

### 自动化

**初始状态没有任何自动化任务。** 用户从能力中心的折叠区域进入 → 选择创建计划 → 填写目标、时间、时区和执行环境 → 检查 → 明确提交后才保存。原型仅模拟本地列表项，不会创建真实定时任务。Webhook 等事件来源属于计划的详细设置。

### 远程浏览器与桌面操作

界面提供目标设备、连接状态、权限范围与操作记录。Android 本机缺乏相应原生控制提供方时，可以选择可用远程 Host；未连接时呈现清楚的不可用原因与下一步，而不是假装已经执行成功。

## 6. 视觉系统与动效

主题采用 **Quiet Instrument / 静谧仪器**：暖灰米主画布、墨绿色主要动作、冷青色运行状态、琥珀色待决策、红色删除与故障；代码与日志保持技术信息精度，普通内容像阅读编辑器一样干净。视觉优先级为“主任务 → 当前结果/状态 → 相关对象 → 更多选项”。

| 视觉项目 | 规范 |
|---|---|
| 最小触控 | 48×48 dp，图标可较小但命中区域完整 |
| 布局 | 320–599dp 单列；600dp 起更宽内容；大屏可双栏预览 |
| 文字 | 主标题 26–40sp，正文 15–16sp，说明 12–13sp；尊重系统字体放大 |
| 间距 | 4dp 基准，常用 8/12/16/20/24/32dp |
| 表面 | 页面与列表主要靠留白和细分隔；避免多个同等抢眼的卡片 |
| 反馈 | 点击即时、列表或状态局部更新、审批及时反映结果 |
| 动效 | 主要页面转场约 220–320ms；抽屉和 Sheet 遵循手势；减少动效时取消空间位移 |
| 遮挡 | 键盘打开后输入不被盖住；Bottom Sheet 覆盖内容且与系统返回一致 |
| 安全 | 用户授权操作有真实对象、实际影响范围、有效期、明确取消路径 |

### Android 原生落地建议

使用 Kotlin + Jetpack Compose + Material 3 的 **Drawer + 单列内容 + 情境 BottomSheet + 必要全屏详情**。建议从语义状态模型中渲染页面，不让 Compose ViewModel 直接暴露 `tool-*`、JSON Schema、Node PTC 或原始 GitHub API 结构：

- `NavigationState(root, section, detail, returnAnchor)` 控制最多三级菜单和任务返回锚点；新页面需有登记归属，阻止加入第四级。
- `TaskUiState` 维护每任务的执行、等待、回执、失败和恢复；事件以 sessionId / turnId / eventId 归并；后台回执是界面状态唯一事实来源。
- `CapabilityUiState` 维护发现到的工具/插件/远程宿主可用性；按平台、已连接账户和权限筛选显露动作。
- `ContextAction` 只在相应对象上出现，关联原请求 ID；Bottom Sheet/弹层关闭时不丢操作状态。
- `SystemDiagnostics` 仅负责必要状态和可追溯记录；长期维护时以自动映射表比对新增功能与已过期入口。

对每个新引入的 Harness 模块，先回答：用户何时需要操作？必须看什么状态？若无需操作，应在什么任务中留下结果？**默认先注册功能能力、呈现策略、触发上下文和状态映射，再决定要不要新增页面。**
