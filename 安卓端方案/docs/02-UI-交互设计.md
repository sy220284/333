# UI 与交互完整设计 V1 · 设计技能 2.4

## 产品视觉策略
设计 2.4 强调“主任务单列、留白、次级内容按需展开、符合 Android 触控习惯”。选「原生材质 + 精密仪器」为核心交互系统，「暖纸 + 活字档案」只用于文档阅读/创作正文；统一语义、字体和间距，不把六套风格混在同一屏。参考《设计技能2.4-10张手机UI提示词.md》的十类真实页面目标。适配 390×844dp 基准，360/411/600/840dp 断点，支持字体 200% 放大、屏幕旋转、深浅色与 Reduce Motion。

## 导航
默认打开“对话”，顶部菜单打开抽屉：最近会话、我的项目、任务与记录、扩展中心、设置。底栏仅保留输入与上下文快捷入口；项目/扩展详情使用返回栈，不做五宫格桌面。平板 >=600dp 提供可收起导航栏；>=840dp 对话和项目内容可双栏。长按内容进入菜单；点击更多才显示高级配置。

## 组件库（用状态而非技术字段驱动）
- AppScaffold（状态栏、安全区、抽屉、主内容、输入栏）
- ConversationItem、UserMessage、AssistantMessage、MarkdownBlock、ReasoningDisclosure、ToolRunRow、FileDiffPreview
- ComposerDock（编辑/附件/语音可选/排队/发送/取消）
- StatusPill（connecting/running/input-required/idle/failed）、RuntimeStatusCard（缺少组件时直接说明）
- WorkspaceRow、FileRow、TreeBreadcrumb、SearchField、EmptyState、ErrorState、LoadingSkeleton
- ModelPickerSheet、ApprovalSheet、QuestionSheet、ContextActionSheet
- TerminalViewport、JobOutputRow、ExtensionRow、PermissionPresetRow、AccountHeader、SettingsItem。
各组件必须设计 idle/loading/ready/action-required/failure/success 六种 UI 状态；审批的允许/拒绝/取消各自独立，拒绝不自动重试。所有列表提供空态与分页/恢复入口。

## UI Token 与可访问性
采用 design/tokens.json；基础单位 4dp，触控区域 >=48dp，信息间距 8/12/16/24，主内容左右 20dp，面板 16dp，圆角 12/16/24。正文字号 14–16sp，标题 20–28sp，说明 12–14sp（依据无障碍缩放）。颜色不能单独表示成功/失败，配合文本和图标；静态正文对比度目标 >=4.5:1。

## 动画与动效（design/motion.json 是代码唯一来源）
- 页面前进：220ms 标准曲线（位移 12dp + 透明），返回与手势同步。
- 抽屉/BottomSheet：300ms 可中断 spring，跟随手指，关关闭时还原焦点。
- 流式回答：只追加实际事件，打字/闪光装饰不得影响阅读；光标以系统节奏缓慢呼吸。
- 工具执行：展开 180ms，收起 150ms；任务运行中只强调状态变化，不对整个卡片持续闪动。
- 新消息：局部 140ms 淡入，不推动用户正在阅读的位置，用户主动滚到底部才恢复自动跟随。
- 权限请求：遮罩 + Sheet 不超过 280ms；取消返回原上下文，保留未提交数据。
- 错误/重试：状态变化立即更新文案，按钮反馈轻振动（遵循系统设置），不使用连续摇晃。
- Reduce Motion：统一变为 0–80ms 透明度/状态切换，取消非必需位移、循环动效。

## 图标及素材规范
`assets/icons` 的 SVG 为 24×24、2px round stroke、currentColor 单色、统一光学中心。适配 20/24/28dp，Android 需转换为 VectorDrawable 或 Compose ImageVector。语义词：chat, project, file, terminal, task, tools, model, account, settings, shield, plug, search, attach, send, stop, chevron, error, success, cloud, device, history 等。对外品牌主图标另行保存，不复用第三方商标。
