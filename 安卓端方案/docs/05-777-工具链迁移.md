# 777 开发工具链迁移到 333 的精确说明

源仓库：`sy220284/777` main `41b2559f90f0f732799cd17bbd003e8a71cb2020`。对照文件：`tools/dev/toolchain-versions.env`、`tools/dev/toolchain-components.env`、`tools/dev/setup-toolchain.sh`、`tools/dev/install.sh`、`.github/workflows/dev-toolchain.yml`、`.github/actions/setup-android-cached/action.yml`、`gradle/libs.versions.toml`、`tools/runtime/prepare-termux-node.sh`。

## 可复用
- 777 版本锁定：JDK >=27 / JVM target 21 / Gradle 9.8.1 / AGP 9.4.0 / Kotlin 2.4.20 / Android API 37 & build tools 37.0.0，Node 主机 >=24，Android Node runtime 26。
- 首次安装缓存：`.github/actions/setup-android-cached` 逻辑及 SHA pin；安卓工程单独 CI，不拖累 333 TypeScript 核心。
- 运行时生产：复用 777 的 Termux 签名校验（InRelease+SHA256）、依赖检查、16KiB ELF 对齐和可执行目录布局思路；需要为 333 Host 可执行包和原生扩展另建 manifest。
- 文件变更范围判定：文档 SVG/Token 只做静态 QA；安卓 Kotlin 走编译+测试；Node/PTY/sandbox/签名改动触发真实设备矩阵。
- 构建产物版本化，缓存分片、hash 校验、带源 commit 信息；重复打包可直接复用可信产物。

## 不照搬
- 777 `ci.yml` 引用 `:harness-core`, `:app`, `ui-pack-v6`、Codex 协议和 `com/labteto`；333 当前不存在这些模块。
- 777 `tools/dev/install.sh` 要求完整仓库配套自制 Artifact，且使用 `DEV777_*` 环境名；333 单独命名 `DSH333_*`，无完整 777 离线 artifact 时进行纯检查，不制造“已装好”的状态。
- 777 的核心业务接口与 DSH Harness API 不同，不能拷贝其 Codex 会话/登录/权限类。
- 777 工具链工作流含 `schedule` 按月刷新。这里不创建定时工作流；仅手动调度和安卓目录变更触发。
- 777 运行时 Node 的 `libdsh_node.so` 及 Termux 动态库只作为已验证的移植基线；必须先确认证书、来源许可、特定 ABI、路径装载与 333 包的 native addon 匹配。

## 本仓落地
`tools/toolchain-versions.env` 与 `tools/check-toolchain.sh` 负责版本、依赖可用性检查；`../.github/workflows/android-plan-ci.yml` 在 PR 运行 Android 专项静态 + Gradle 编译，待 runtime release 产物补齐后扩展设备矩阵。稳定使用单独的 `安卓端方案` 目录，保留上游 333 自有 CI。版本变化必须先与 777 main 核验，再修改唯一锁文件和 Gradle 声明。
