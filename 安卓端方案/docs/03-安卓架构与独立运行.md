# Android 接入、平台适配与独立运行架构 V1

## 架构
- UI：Compose Material 3 + design/tokens.json；页面 ViewModel/Store 只订阅业务状态。
- Domain：SessionRepository、WorkspaceRepository、AgentActionRouter、ExtensionRepository、RuntimeStatus。
- Transport：OkHttp HTTPS/loopback HTTP JSON-RPC + Cookie + WSS/WebSocket mux，strict envelope/id，断线补页。
- Runtime：CoreRuntimeSupervisor（进程所有权）→ Android Node 运行时 → 333 按官方 CLI profile 启动的 DSH Host。
- OS：Storage Access Framework、PackageManager、ForegroundService、WorkManager（仅产品确有后台任务时）、PTY/进程适配、Android 沙箱。

## 原始协议（从源码核验）
1. 发起方获取 *用户当前明确启动的 Host* 提供的启动 token，`GET /connect?token=...&interactions=answer`，交换完成返回 302 + `Set-Cookie`；令牌仅用于交换，不记录 URL/日志。独立 API Peer Cookie 通过 Host 信任检查。
2. POST `/api/session/create` Body `{"type":"client-request","rpcId":"UUID","method":"session/create","payload":{"args":{"request":{...}}}}`。
3. 结果 `{"type":"server-response","rpcId":"同一UUID","result":{"ok":true,"value":{"sessionId":"..."}}}`。严格核对 rpcId、method、content type；错误返回 `{ok:false,error:{code,message,details}}`。
4. WebSocket `/api/remote.mux`：发 `{type:"open",streamId,endpoint:"session/follow",payload:{args:{request:{address:{kind:"session",sessionId},assistantStream:true}}}}`。接 `item/error/end`；关闭时发送 `cancel`。
5. `session/follow` 的 `snapshot` 建立 baseline，后续 durable event 以 cursor 合并；非持久 assistantStream 使用 revision/index，不按普通文本事件盲拼；重连先恢复 snapshot，再增量。
6. `/api/session/uploadFileBinary` 使用原始字节 POST，query 为 sessionId/name/mediaType，受同一身份保护。

## Android Host 独立运行必须具备
| 能力 | 设计路径 | 验收证据 |
|---|---|---|
| Node.js | 参考 777 的签名 Termux 包构建器，Node 26，libdsh_node.so 嵌入 jniLibs，验证包签名、SHA-256 与 16KiB ELF 段对齐 | 真机 arm64 执行 node --version |
| Host 发布物 | 在 CI 构建 333 pnpm Host bundle，并对每个可执行/依赖作 Android ELF 与 require/import 审核；私有 assets 中含 manifest 和 hash | 断网冷启动加载 dsh profile |
| 依赖库 | Node native addon、pty、sqlite、ffi 按目标 ABI/Android API 逐个验收 | 运行核心工具 matrix |
| CLI 启动 | 复用官方 `dsh` profile 入口，启动参数和启动 token 由 Supervisor 持有；真正 READY 以 Host HTTP/API handshake 为准 | core PID + handshake + session/create |
| 生命周期 | 前台可见时绑定 Service；后台长操作用通知可见 ForegroundService，退出关闭进程树，重启用 event log 恢复 | 用户杀进程/旋转/重开 |
| 安全 | 用 Android 进程权限、私有目录与显式授权替换 Linux bwrap/Landlock；执行能力有真实约束再开放 | 沙箱负向测试 |
| Shell/PTY | Android 可用的 shell 后端 + 双向 PTY，退出/大小变化/Unicode/取消 | 交互命令测试 |
| FS | app 私有工作区作为默认；外部文件通过 SAF URI 授权并可靠复制/同步，禁止把 content:// 当普通 POSIX 路径 | 生命周期与访问权限测试 |
| Plugin/MCP | 默认随 APK 装入安全基础能力，stdio MCP 依赖 Android 可执行环境，HTTP MCP 遵循隔离与凭据存储 | 服务重启、调用、卸载 |
| 网络 | 远端只能 HTTPS/WSS，loopback HTTP 仅限本机，证书严格校验，不接受所有证书 | MITM/域名/无网络测试 |
| 导入导出 | Android 分享及文档选择器，与 Host 附件存储建立有界数据桥 | 多尺寸文件上传下载 |
| 诊断 | Host 存活、API 可用、模型可用、工具可用各有状态；异常可阅读并复制日志 | 可复现错误提示 |

## 四级运行状态，防止“显示已启动，实际不可用”
`NotInstalled`（运行时缺失）→ `Preparing`（校验清单/解包）→ `Starting`（有 PID）→ `Ready`（实际 RPC 通过）。失败分为 `MissingBinary`、`HashMismatch`、`MissingAddon`、`UnsupportedSandbox`、`HostExit`、`AuthRejected`、`TransportLost`。UI 显示每个阶段和下一步实际动作。真正 Ready 后才启用新会话发送。

## 实现顺序与依赖
先固定 Remote 契约 + 组件/端到端观测；再落实 Node/Host 可执行包；再适配 subprocess、PTY、sandbox；最后闭合插件与 MCP 安装、后台恢复、断网使用与 release 签名。安卓本地进程不继承桌面 Linux 的权限模型，须重新选择可验证的隔离边界。
