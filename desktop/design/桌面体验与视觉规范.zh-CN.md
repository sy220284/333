# 摇摇车桌面工作台：2026 高品质体验设计规范

> 适用范围：PR19 Electron / React 工作台的十个导航视图，视觉和交互与真实 SDK、Agent、任务簿、项目文件及权限网关保持一致。
> 设计状态：本文件记录已实施的 UI 规范、可验证的交互和完整的下一阶段设计验收条款。Figma 原文件在 Starter 调用额度恢复后按此规范同步，不以静态概念图替代运行界面。

## 0. 产品定位与设计原则

目标用户是每天处理长任务、代码和多智能体协作的开发者与专业创作者。以“任务推进与掌控”代替“展示指标”，以桌面工作台而非传统后台仪表盘组织界面。

借鉴产品与转化机制：

| 参考 | 借鉴核心 | 摇摇车独有强化 |
|---|---|---|
| Linear | 明确的信息层级、整洁密度、弱分隔、强键盘操作 | 同一入口同时覆盖任务簿、工作项审批和运行记录 |
| Cursor | AI 任务、代码、Agent 同工作区 | 消息→任务→文件差异→审批→验证形成完整可返回链路 |
| Raycast | 命令入口、快速搜索及无鼠标操作 | Ctrl/Cmd+K 覆盖十个页面及工作区操作，未来延伸到真实任务与会话 |
| VS Code | 层级导航、文件树、终端、Git 语义、可折叠上下文 | 将 Agent 执行时间线与具体文件修改关联呈现 |

严守的原则：
1. **每个页面只有一个首要操作。** 左右辅助模块不得压过当前目标。
2. **视觉要指向状态。** 蓝色表示选中和可行动作；青绿表示就绪/成功；琥珀表示等待/待审核；红色表示错误；状态同时有文字，不依赖颜色辨认。
3. **空状态是流程入口。** 明确下一步操作和触发结果，不堆无意义插画。
4. **一切工作都可追踪。** 任务、会话、文件、模型、权限与结果要能相互定位。
5. **本地执行语义明确。** 持续任务的暂停、续跑和授权由真实宿主返回，不能以动效代替执行证据。
6. **高密度与阅读专注并存。** 工作面板适度紧凑，AI 长文、代码和差异保持足够行高。

## 1. 视觉基础与语义变量

按 `desktop/src/styles.css` 当前 CSS 变量维护源码真值；在 Figma 创建同名变量与 Dark/Light 两个 mode，并保留透明色层叠的变量约定。设计不再使用每张画板单独写死颜色的做法。

| 语义 token | Dark | Light | 用途 |
|---|---|---|---|
| `--bg` | `#0b1019` | `#f4f6fa` | 画布底色 |
| `--surface` | `#141c2a` | `#ffffff` | 一级容器 |
| `--surface2` | `#1b2637` | `#f8fafe` | 次级区域/输入 |
| `--surface3` | `#243147` | `#eef2f9` | 状态悬停/强调 |
| `--line` | `#2b3950` | `#dce3ee` | 轻量分隔与轮廓 |
| `--text` | `#f0f4fd` | `#1b2941` | 正文 |
| `--muted` | `#a1afc5` | `#53647c` | 次要说明 |
| `--subtle` | `#7e8da7` | `#6d7c93` | 辅助元数据 |
| `--accent` | `#8799ff` | `#566fe1` | 主要选中与聚焦 |
| `--accent-bright` | `#b5beff` | `#425ac3` | 可点击内容 |
| `--mint` | `#72dec1` | 继承既有亮色变量 `#1d9778` | 成功/已连接 |
| `--amber` | `#e8b57a` | `#ad7131` | 需人工介入 |
| `--danger` | `#e995a1` | `#c85c69` | 错误与拒绝 |

字体：优先 Inter 与系统无衬线，中文使用“苹方 / 微软雅黑 / Noto Sans SC”系统回退；代码 `ui-monospace, SFMono-Regular, Consolas`。主标题 24–30 px、节标题 15 px、正文 12–13 px、辅助说明 11 px、底部元信息 10 px。正文行高 1.7–1.83，代码 1.7。尽量使用 4/8/12/16/24/32 px 间距级差。常规面板圆角 14 px；悬浮命令中心 19 px；按钮 9–11 px。边框 1 px，重点区域允许轻微内侧高光；避免满屏强发光和叠加过多玻璃层。

动效：悬停 120–180ms；面板出现 200ms 左右；变化以透明度/位置微调为主。所有动效遵守 `prefers-reduced-motion` 与应用内“动态效果”开关。长期任务运行状态优先真实时间/文字，动画仅辅助识别，不能伪造进度。

## 2. 整体空间结构和断点

1440×900 为设计基准（CI 实际 Electron 烟测 1280×920），三栏：左侧约 216–238 px 导航、右侧约 236–273 px 上下文、中央自适应；顶部 62 px、底部 31 px。保持垂直阅读栅格，内容最大宽度建议 1060 px，工具与任务卡片填满有效空间。

响应策略按当前代码：
- `>1370`：完整三栏，四项概览指标横排；
- `1130–1370`：较窄三栏，指标两列；
- `940–1130`：隐藏右栏，操作仍由设置和状态入口完成；
- `860–940`：导航收为图标轨道；主内容紧凑并保留任务输入；
- 低于 860：正式 Electron 窗口最小宽度限制，独立嵌入式预览可另行采用移动布局。

要求：任何断点不能隐藏正在等待的工具审批入口；窄窗状态不能让导航按钮无 accessible label。相同项目显示路径的地方可以缩略，悬停应能看到完整路径。

## 3. 十个页面的完整高保真设计规格

### 3.1 工作台概览｜个人指挥中心

基线：显示项目、会话、模式、任务和模型。升级：
- 头部项目定位、最近一次任务和“开始新任务”主行动；
- 四指标保留，但数据为实际会话数/团队模式/任务数/模型数；
- “继续工作”呈现近五条可恢复会话，时间及状态优先于装饰；
- 任务卡片以“目标→下一步→是否待审”呈现；
- 空状态采用明确的“创建会话/创建任务”操作，不用大面积空白海报替代工作入口。

### 3.2 AI 对话｜长任务阅读与执行中心

- 顶部：真实会话运行状态、模型切换、权限模式、中断入口；
- 主消息：用户、助手、工具三类视觉分离。助手回答支持标题、行内代码、代码块、列表、引用与安全 HTTP(S) 链接，用户/工具消息原样安全显示；
- 当前已实施：最多先挂载最近 120 条消息，单次展开更早 120 条；阅读旧消息时不强拉滚动位置；“回到最新消息”可见；
- 代码块必须自带语言栏与水平滚动；后续代码复制、差异定位、文件锚点应基于真实内容语义；
- 输入区：清晰展示执行模式、发送快捷键、是否可发送；空状态列出真实任务入口，不放虚假的“建议已完成”状态；
- 审批请求浮层显示工具名、目标会话、真实参数及本次允许/拒绝；并发审批按会话追踪。

### 3.3 智能体团队｜执行拓扑

- 顶部模式切换“主智能体＋子智能体 / Super Agents”，明确新会话生效；
- 有团队时左列队伍清单、右侧成员实时状态和模型，强调负责人、执行中、空闲、失败；
- 增加以流程为中心的成员列表与任务链接；无成员时引导到任务创建，不产生模拟智能体；
- 接下来设计团队通信/共享任务簿/停启控制的可见独立区域，必须映射后端真实事件。

### 3.4 长期任务｜任务簿与可追踪队列

- 左：任务选择/新建；右：目标、状态、操作、工作项/检查点/历史结果；
- 每张工作项显示排队、执行中、待审、已完成、失败或中断，动作按真实状态显隐；
- 队列的“持续推进”必须由用户明确发起；最多并发三项；待审停留供人工批准；
- 未来把“目标—任务—执行—审查—恢复”统一为清晰步骤序列，状态和恢复入口不可仅靠侧栏碎片。

### 3.5 项目文件｜工作区与差异一体化

- 左：工作区文件树，目录优先、稳定排序、分页可继续加载，保护路径与读取上限；
- 右：文本文件编辑+保存确认；下：Git 状态与已暂存/未暂存差异；
- 字体、行号/差异块、文件路径采用编辑器级密度；长期目标是修改定位与安全提交，不引入假编辑器功能。

### 3.6 模型管理｜事实与能力矩阵

- 读取 SDK 实际返回的模型标识、服务商和描述；可选与当前模型需要有明确状态；
- 凭证管理显示已配置/未配置，密钥只输入不回显，本机保存有系统确认；
- 后端的上下文长度、输出与推理档位在后续统一扩展读取接口后才呈现；不能把未校验的常量设计成实时数据。

### 3.7 技能与 MCP｜可操作的工具架

- Skills / MCP / 插件分区；真实 MCP 服务器支持启停、添加、移除、诊断；
- 现有技能与插件管理入口仍主要靠 AI 指令，后续必须接通原生列表/启用/安装/更新/来源详情才能认定完整；
- MCP URL 授权必须明确 HTTPS 目标、浏览器确认与取消状态，不能自动放行。

### 3.8 GitHub｜仓库工作台

- 当前已接入本地 Git 状态与差异、可由 AI 发起审查；
- 设计目标：分支、PR、CI、审查记录、变更与授权形成同页面可追踪流程；真正的 PR 列表/提交/工作流要等待连接真实 GitHub 接口；
- 视觉上区分本地状态和远端状态，避免把本地 Git 结果伪称 GitHub API。

### 3.9 历史记录｜工作连续性

- 会话列表、归属项目、最后时间、历史只读与继续会话操作；
- 从历史进入先只读，用户发送新消息后恢复真实 SDK 上下文；
- 后续可增加关键词、模型、状态和日期过滤、分页和打开最近任务。

### 3.10 设置与权限｜执行安全中枢

- 审批队列需要区分会话，提供危险操作参数的清楚预览；
- 深色主题、动态效果、详情面板控制跨启动保留；
- 显示模型和执行模式变化影响的作用范围；
- 对异常连接采用明确的重连和故障详情，禁止静默“成功”提示。

## 4. 需要在 Figma 建立的可复用资产

在已有九张画板上新增“历史记录”第十屏。不要直接扔掉此前设计：建立 `00 Foundations`（颜色/字阶/间距/半径/阴影 Dark+Light）与 `01 Components`（可变体组件）并逐屏替换。

组件种类及应覆盖的关键状态：
1. Navigation Item：default / hover / active / badge；Sidebar expanded / compact。
2. Button：primary / secondary / ghost / danger；default / hover / focus / disabled / loading。
3. Text Input + Search：empty / focus / filled / invalid；包含快捷键提示。
4. Status Pill：online / running / paused / review / failed / completed；文字+色点。
5. Card + List Row：default / selected / hover / loading / error / empty。
6. Chat Message：user / assistant / tool / streaming；带代码块、列表、链接、附件占位规范。
7. Agent Member / Job：running / idle / review / completed / failed / interrupted，包含权限提示。
8. Permission Dialog：normal / dangerous / external URL / concurrent queue / blocked。
9. Workspace Tree / Diff：directory / file / selected / modified / staged / unstaged / page load。
10. Inspector Pane / Command Palette：expanded / collapsed / search results / zero results / keyboard navigation。
11. Theme specimen：每个关键组件的亮/暗模式，避免单画板只画暗色。
12. Responsive screens：1440、1280、940、860 基准状态与弹窗遮罩。

所有有结构关系的组件使用 Auto Layout；动态参数与文字可调整长度，长目标和长路径可换行；重点按钮/卡片使用真实组件实例，变量绑定颜色、间距与半径，而不是用独立矩形临摹。

## 5. 可量化的体验验收

- 十页导航：桌面键盘、鼠标均可访问，每页不少于一个真实可用操作，空状态可返回任务主线；
- UI 屏幕：1440/1280/940/860 下无核心内容裁切、无菜单无法返回、无长文本溢出；
- 阅读：260 条长记录只初始挂载 120 条；长内容不会跳离用户阅读位置；
- 命令中心：Ctrl/Cmd+K 搜索 10 页与常见操作，Esc 可退出，方向键与 Enter 真实执行，背景元素不能误操作；
- 本地偏好：主题、动效、详情面板重启后保留；
- Git：已暂存与未暂存差异明确可辨；文件超过一页有继续加载而非静默丢弃；
- 权限：来自不同 SDK 会话的审批明确分组并正确返回其请求；
- 外观：深浅主题、空/加载/错误/审批/完成状态均有对应画板及运行截图；
- 测试：TypeScript、Vitest 交互、Electron 构建、真实 Linux 安装/运行截图/Host 通信，最终 Win/mac 安装实测与长时间模型调用逐项验收。
