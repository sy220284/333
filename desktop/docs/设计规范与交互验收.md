# 摇摇车 Desktop · AI 智能体工作台设计规范与交互验收

设计源文件：[Figma 九大页面矩阵](https://www.figma.com/design/7tMuuOySLcOEtoKYftLuEV)

## 产品定位

围绕 AI 对话、智能体协作、任务簿和真实工作区操作设计桌面工作台。所有显示的服务状态和执行数据须来自桌面网关、SDK 或本地真实文件。模拟/演示数据只能留在 Figma 设计稿。

## 页面信息架构

| 页面 | 核心动作 | 数据来源 | 无数据处理 |
| --- | --- | --- | --- |
| 工作台概览 | 新建会话、继续工作、跳转任务 | sessions.list / agents.overview / missions.list / models.list | 发起首个会话 |
| AI 对话 | 模型选择、发送、取消、工具审批 | sessions.* / session.message / permissions.* | 引导输入任务 |
| 智能体团队 | 主子模式、Super Agents、任务控制 | agents.* / tasks.* | 引导启动协作 |
| 长期任务 | 创建目标、入队、最多三项并行、人工审核、暂停、恢复 | missions.* / missions.jobs.* | 创建首个长期目标 |
| 项目文件 | 浏览、读取、编辑、保存、Git 差异 | workspace.list/read/write / Git | 选择目录/文件 |
| 模型管理 | 模型发现、切换、配置 API Key | models.list / providerApiKeyVault | 引导配置服务商 |
| 技能与 MCP | 调用现有技能/MCP，诊断配置 | SDK 与已接入的工具 | 提示当前真实支持范围 |
| GitHub | 本地 Git 状态、AI 代码审查 | Git / SDK GitHub 工具 | 说明工作区未初始化 |
| 设置与权限 | 单次允许/拒绝、MCP elicitation、主题与动效 | permissions.* / host.* | 无待审权限 |

## 布局尺寸与使用习惯

- 设计基准：1440 × 900。左侧 238 px 导航，顶部 62 px 工具栏，右侧 273 px 上下文检查器。
- 可用主视图按窗口宽度弹性伸缩，窗口缩小时折叠右侧信息层；进一步收窄时只显示导航图标。
- 工作任务是导航主轴，深度操作在内容区完成，审批使用始终可见的系统级覆盖层。
- 支持 Ctrl/Cmd+K 搜索导航、Ctrl/Cmd+N 新建会话、Ctrl/Cmd+Enter 发送、Esc 退出搜索。
- 正文 12–14 px；页面标题 27 px；支持键盘焦点；窗口缩放时不得出现横向无意义滚动。
- 有长列表的部分采用真实数据分页或项目范围加载。历史会话使用独立分页参数。

## 色彩和材质

| 语义 | 深色值 | 用途 |
| --- | --- | --- |
| Background | `#0A101B` | 主底色，避免大面积纯黑 |
| Surface | `#111B2B` | 侧栏、内容、模态 |
| Surface elevated | `#172338` | 卡片、工作区 |
| Border | `#293A55` | 层次分隔、焦点边界 |
| Text | `#EFF4FF` | 主文字 |
| Muted | `#8A9AB3` | 次级文字 |
| Accent | `#8195FF` | 品牌色、主要操作 |
| Success | `#69DFBE` | 已连接、已完成 |
| Warning | `#E8B57A` | 审批、等待、待审 |
| Danger | `#E995A1` | 失败、危险操作 |

- 使用高低明度区分三层材质：底层、普通面板、浮起卡片；模糊背景只用于顶栏和安全审批层。
- 重要按钮保持高对比，次级操作弱化，最多一个主行动作抢占当前视觉焦点。
- 边框为轻微透明度、圆角 10–20 px、阴影低对比；深色和浅色主题都要清晰。
- 图标使用 Lucide 统一线性语言，不混用数套图标风格。

## 动画与交互

| 场景 | 动画策略 | 目标时长 |
| --- | --- | --- |
| 页面切换 | 淡入 + 5px 浮起 | 260ms |
| 按钮悬停 | 颜色/阴影变化 + 1px 浮起 | 180ms |
| 导航悬停 | 颜色变化 + 2px 水平微移 | 180ms |
| 消息进入 | 透明度与纵向过渡 | 220ms |
| 权限弹窗 | 背景模糊、模态上浮及轻微缩放 | 240ms |
| 概览装饰材质 | 低幅度缓慢浮动 | 6s 循环 |
| 实时消息 | 直接流式追加，避免全文重新动画 | 每个 SDK 增量事件 |
| 长任务状态 | 使用明确状态色与文字、避免无止境骨架闪烁 | 事件驱动 |

系统设置“减少动态效果”时自动关闭动画；用户也可在设置中手动关闭全部过渡。滚动到新消息应尽量避免影响用户手动查看的历史内容（目前待专项实测）。

## 可访问性和状态规范

- 每个图标按钮有可访问名称，列表行和弹窗可用键盘操作。
- 危险权限与文件修改需明确批准，允许/拒绝两种行为要能对应到真实后台响应。
- 所有操作提供执行中、成功、失败、无内容四类反馈；错误显示明确原因及修复入口。
- 主模型和任务模式在多个页面保持一致，同一个工作区状态只维护一份。
- 输入 API Key 不回显、日志不可记录原文。Vault 存储遵循原有服务商密钥管理方案。
- 任务簿入队/列出不自动启动子智能体，执行须由用户明确操作；最多并行三项。

## 架构与发布验收

- React 渲染进程只通过 preload 白名单调用 Electron 主进程；主进程连接现有 desktopHost，不复制 SDK 执行引擎。
- 主进程采用 `contextIsolation:true`、`sandbox:true`、`nodeIntegration:false` 与 CSP。
- 工作区路径通过 `realpath` 校验，保存文件遵循人工确认并保留权限位。
- CI 执行 `npm test`、`npm run typecheck`、`npm run build`，并检查 Electron 主进程、preload 及页面产物。
- Windows、macOS、Linux 均需执行真实安装、启动、IPC、权限、任务、模型和卸载测试。最终发行包与提交 SHA 严格对应。
- 旧 React/Ink 界面在完成功能覆盖率 100% 及跨平台实测后清理，CLI 无界面能力保留。
